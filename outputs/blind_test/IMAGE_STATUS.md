# 盲测示意图可用性状态（必须转达给 SCORER）

> 生成背景：BLIND-408 预测者报告"2 张 PNG 是浏览器报错页"，我复核后**确认成立**，
> 定位为**我方管线的 bug** 并已修复。本文件记录最终状态与对评分的影响。

## 一、根因（已修复）

`make_blind_test.py` 的 `svg_to_png()` 用 Chrome headless 渲染 SVG，但**从不校验渲染结果**。
源仓库有 2 个 SVG 是**畸形 XML**，Chrome 把它们渲染成**错误页**
（粉红横幅 `This page contains the following errors`），而不是图。
产出的 PNG"看着有内容"，实际是错误页——预测者据此说"图无法判读"，
而这**不是预测者的失误，是我方管线的 bug**。

**修复内容**（两道闸门）：
1. 渲染前用 XML 解析器**预检** SVG 合法性（`svg_wellformed`）——畸形则不渲染；
2. 渲染后粗检是否为错误页（`looks_like_error_page`，检测顶部粉红横幅）——是则丢弃。

修复后重跑，`render_failed` 被明确报告，不再产出误导性的错误页 PNG。

## 三、两个独立的问题，不要混为一谈

1. **畸形 SVG（2 个）** —— 源仓库的数据缺陷，**无法修复**。对应题目的图**彻底不可得**。
2. **无文字标注（4 个全部）** —— 这些 SVG 是**矢量图形**（框、线、箭头），
   原书中的文字标注**没有被保留**（推测是 PDF 转 SVG 时只提取了图形层）。
   所以即使图能渲染，**位宽、字段名、设备名、IP 等文字信息也读不到**。

**关键**：第 2 条意味着**任何依赖图中文字信息的作答都是不可得的**，
不只是那 2 张畸形图。BLIND-408 的做法（对读不到的项标 UNKNOWN）是**正确的**。

## 四、对 SCORER 的强制要求

| 题目 | 受影响的小问 | 评分要求 |
|---|---|---|
| `408-26-A-T44` | 依赖示意图的 (1) ① ② | **必须判 `UNVERIFIABLE`**，不得判 MISS |
| `408-22-A-T47` | 依赖拓扑图的全部小问 | **必须判 `UNVERIFIABLE`**，不得判 MISS |
| `408-18-A-T44` | 依赖图中位宽/字段名的 (1)(3) 数值与 (4) 计算 | 结构预测可正常评分；**纯文字依赖项判 `UNVERIFIABLE`** |
| `408-18-A-T45` | 同上 | 同上 |
| `408-26-A-T47` | 题面数值自足 | 可正常评分 |

**判据**：若预测者在 `uncertainty` 里写明"无法读取示意图/图缺文字标注"，
且该小问确实依赖图中信息，则**该小问记 `UNVERIFIABLE`**，
并在 SUMMARY 里**单列** `UNVERIFIABLE` 计数——**它既不是 HIT 也不是 MISS**。

**为什么这条必须严格执行**：把"我方管线读不到图"记成"预测者 MISS"，
等于用数据缺陷去惩罚预测者，会**系统性低估**词表的预测力。
这与"把记忆当预测力"是方向相反、但同样严重的失真。

## 五、给后续题包的建议（已写进工具）

1. **不要假设 SVG 一定可渲染**——`make_blind_test.py` 现已强制 XML 预检 + 错误页检测。
2. **不要假设 SVG 里有文字**——本数据集 4/4 张图都无文字标注。
   若题目的图依赖文字，**应在题包头部显式声明"该图缺文字标注"**，
   而不是让预测者自己发现。
3. 若将来需要真正可读的图，应改为**从源 PDF 重新提取含文字层的图**，
   或使用嵌位图（本数据集的 SVG 里其实内嵌了 base64 位图，但文字仍是轮廓化的）。
