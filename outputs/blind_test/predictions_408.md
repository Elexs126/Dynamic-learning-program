## 408-26-A-T41

**problem_geometry**
- `representation_issue`: 目标的代价函数是 `|data − K|`（距离序），而存储结构提供的是 `data` 的键序（BST 中序有序）。**搜索序与目标序不同构**——树只告诉你 K 落在哪一侧，不直接给出"离 K 有多近"。
- `coupling`: "全局最小距离 best 的维护"与"是否进入某棵子树"的剪枝判定耦合在一起；同时"输出所有并列最小者"要求不能命中即返回，最优性判定与遍历终止条件耦合。
- `dependency_structure`: 从根到叶的下降依赖链：`当前结点值 vs K` → 决定进入哪侧子树 → 更新 `best` → 用 `best` 反查另一侧子树是否仍可能产生更小距离。
- `information_risk`: 若只保留"最近一次比较结果"而不保留全局 `best`，会不可逆地丢掉全局最优信息；若遇到第一个候选就返回，会丢掉并列解（题面明说"所有结点"）。
- `state_transition_structure`: **是**。状态 =（当前结点指针，当前已知最小距离 `best`，结果集合）；事件 = 访问一个结点 / 下降到子树。
- `resource_or_bottleneck_structure`: **是**。瓶颈是"每个结点上只用 O(1) 的判据决定是否还要进入某棵子树"。判据不完整 → 漏解；判据过弱 → 退化为 O(n) 全树遍历。

**main_obstacle**
问题的两个序不一致：树的有序性由 `data` 给出，而目标是 `|data − K|` 的最小化。这导致"最近点"**不落在单向下降路径的终点上，而落在路径的边界处**；同时"所有并列最小"要求把"最优性判定"从一次性动作改造成随遍历持续维护的不变量。难点不是"会不会写递归"，而是：剪枝判据必须同时保证"不漏解"与"不退化成全树扫描"，这两个要求由同一个判据承担。

**trigger_candidates**
1. 看到目标函数是 `|data − K|`，而存储结构只提供 `data` 的键序 → 警觉**搜索序 ≠ 目标序**，不能按普通 BST 查找单向下降到底就收工。
2. 看到"绝对值最小"却未说明唯一 → 警觉**可能有多个并列最小结点** → 不能用单个"更近就替换"的变量，必须同时维护并列集合。
3. 看到"**所有**结点" → 警觉不能命中即返回，终止条件与最优性判定必须分开。
4. 看到"二叉搜索树"这一前提被特意写出 → 警觉有序性是被允许使用的资源，最近点只可能出现在 K 的**中序邻域边界**上，而不是任意位置。
5. 看到"输出该绝对值与结点中的关键字" → 警觉目标是 `(最小距离, 全部达到该距离的关键字)` 这一**成对**结果，状态里必须同时带标量最优值与集合。

**predicted_first_transition**
- `before_state`: 问题 = "在整棵 BST 中找出使 `|data − K|` 最小的所有结点"；候选集合 = 全部结点；树序与距离序不一致，无法直接下降。
- `operation`: `RESTRICT_SLICE` —— 用 BST 的序结构把候选集合从"整棵树"限制到"K 在中序意义下的邻域边界切片"。
- `after_state`: 问题从"全树搜索 + 比较"变成"在 O(h) 条边界候选上比较距离"，同时明确需要维护 `best` 与并列集合。
- `why`: 题面显式给出"二叉搜索树"存储 → 序结构是被授权使用的资源；距离函数沿中序是单峰的，最小值必然出现在 K 的两侧边界而非中间。
- `basis`: `pattern_recall`
- `basis_note`: "BST 中找最接近 K 的值 ⇒ 就是 K 的前驱/后继"是我读到题面时的**第一反应**，这个反应来自见过此类题型，而不是从题面逐字推出。题面只给了 BST 定义，没有给出"前驱/后继"这一步。

**predicted_second_transition**
- `before_state`: 候选已限制到边界切片，但仍是一个"两侧各取极值再比较"的动作，且并列集合尚未落地。
- `operation`: `INFORMATION_AXIS_DECOMPOSITION` —— 沿 K 把候选轴劈成两条互不干扰的独立轴：轴一 = "所有 < K 的关键字中的最大值"，轴二 = "所有 > K 的关键字中的最小值"；各自取极值后再比较，并列集合由两侧同时可能贡献。
- `after_state`: "最近"被分解为两个单侧极值问题，每个都可用标准 BST 下降在 O(h) 内解决；并列最小者 = 两侧所有达到该距离的结点（含重复关键字情形）。
- `why`: 题面要求"所有"结点 → 单侧极值框架天然给出"哪些侧可能产生并列"；同时 BST 的左右子树语义天然就是"小于 K / 大于 K"两条轴。
- `basis`: `from_problem_statement`

**system_state**
BST 的当前访问结点 + 路径上"≤ K 的最大值 L"与"≥ K 的最小值 R" + 当前 `best` + 已收集的并列结果集合。

**resources**
- 时间：目标是 O(h)（h 为树高），而非 O(n)
- 递归/迭代栈深度：O(h)

**agents_or_components**
BST 结点（`data` / `left` / `right` 三个域，题面已给结构体）。

**invariants**
- `L ≤ K ≤ R`（L、R 恒夹住 K）
- `best = min(|L − K|, |R − K|)` 恒为"已访问部分"的最小距离（随遍历单调不增）
- 结果集合恒满足"其中每个结点的 `|data − K|` 都等于当时的 `best`"

**state_transition**
- `根 → 按 data 与 K 的大小关系下降到左/右子树`
- `data == K → 距离为 0 → 立即收口（0 是距离下界，不可能更优）`

**bottleneck**
"是否进入另一侧子树"这一剪枝判定。它是唯一决定复杂度是 O(h) 还是 O(n) 的环节，也是唯一可能漏解的环节。

**local_vs_global_effect**
局部决定"只往左走"会丢弃整棵右子树 —— 只有在 `best` 已被全局维护的前提下才安全。局部剪枝的正确性**依赖** `best` 的全局性，这是本题局部动作与全局正确性的接口。

**layer_interface**
抽象算法层（"最近值 + 并列集合"）→ 存储层（`left`/`right` 二叉链表指针）。题面给出的结构体就是这一接口的定义。

**UNKNOWN**
1. 题面未说明 BST 中**关键字是否允许重复**。若允许重复，"所有并列最小"是否包含同一关键字的多个副本无法确定 → 影响状态里集合的语义。
2. 题面未给出对空间复杂度的要求，因此"是否允许 O(n) 的辅助中序序列"这一路线是否被判为合法，无法从题面确定。

**uncertainty**
最没把握的是**第一步是否真的是"前驱/后继"式的边界切片**。如果标准解走的是"中序遍历整棵树、边遍历边维护 best"（O(n) 但绝对正确），那我的第一步与第二步都是结构性多余的，会记 MISS。我无法从题面判定命题人是否强制要求 O(h)。另：`basis: pattern_recall` 已如实标注——"前驱/后继"这一反应确实是题型记忆。

## 408-19-A-T42

**problem_geometry**
- `representation_issue`: 三条要求（可增长 / 空间只增不减且可复用 / O(1)）同时压在"队列占用空间"这一个概念上，而"空间"在顺序存储与链式存储下是完全不同的两种对象（一段连续数组 vs 一堆离散结点）。**表示未定之前，约束无法逐个检验。**
- `redundant_freedom`: 信号量式的自由度：判空/判满判据的具体形式（指针相等 / 计数 / 标志位）有多解，题面只约束"必须 O(1) 可得"。
- `coupling`: "空间增长"与"判满"耦合（顺序存储下判满依赖容量）；"空间复用"与"归还"耦合（链式存储下复用通常靠 `free`，而 `free` 会让占用空间减少，与③冲突）。
- `dependency_structure`: 依赖序：先定存储结构 → 才能定判空/判满判据 → 才能定入队/出队过程。前一步未定，后两步无意义（题面小问顺序 (1)(2)(4) 正是这个序）。
- `information_risk`: 若把"空间只增不减"理解为"逻辑长度只增不减"，会丢掉"物理占用单调"这一关键信息，从而误选顺序循环队列。
- `state_transition_structure`: **是**。状态 =（逻辑队列内容，front/rear 或 head/tail，已分配空间总量）；事件 = 入队 / 出队 / 空间增长。
- `resource_or_bottleneck_structure`: **是**。核心资源就是"已分配的存储空间"，且它被施加了**单调不减**的约束；瓶颈是"空间增长动作"——它是唯一可能破坏 O(1) 的环节。

**main_obstacle**
三条要求互相牵制，且牵制的交点落在"判满"上：
- 顺序存储下，"可复用"要求循环，而"循环 + 判满"必须依赖容量；一旦容量用尽就要扩容，而扩容通常需要搬迁（非 O(1)）；若为了不搬迁而拒绝扩容，又违反②。
- 链式存储下，"可增长"与 O(1) 天然满足，但"可复用"的常规实现是 `free` 归还系统，这会让"占用空间只增不减"失效。
因此难点不在实现细节，而在于：**必须把"逻辑队列的可用性"与"物理空间的占用/归还"分成两个独立的状态量**，并给出一个既不依赖总容量、也不依赖释放动作的 O(1) 判据。

**trigger_candidates**
1. 看到"整个队列所占用的空间只增不减" → 警觉**"归还/释放空间"被明令禁止** → 直接排除"出队即 `free`"的常规链式队列。
2. 看到②"入队时允许增加空间"与③"出队空间可重复使用"同时出现 → 警觉"可增长"与"可复用"在同一存储表示下可能相撞（顺序循环队列的假溢出 vs 扩容搬迁）。
3. 看到④"入队/出队时间复杂度始终保持 O(1)"与②并列 → 警觉**扩容不能是整体搬迁**（那是 O(n)）→ 排除"满则重新分配并复制"的顺序方案。
4. 看到"画出队列的初始状态"与"给出判断队空和队满的条件" → 警觉判空/判满判据是本题的收口点，且必须是**不依赖容量计数**的判据。
5. 看到"画出第一个元素入队后的队列状态" → 警觉初始状态中"空/满如何区分"的表示（例如头结点是否占位、尾指针指向何处）会决定后面所有判据，初始表示选错则后面全错。
6. 看到 (1) 直接问"应选择链式还是顺序" → 警觉**这个选择不是显然的**，命题人预期考生会先被顺序循环队列的直觉吸引，再用③把它否掉。

**predicted_first_transition**
- `before_state`: 三条要求同时作用于"空间"这一未定表示的对象上；无法直接判断任何一条是否被满足。
- `operation`: `CONSTRAINT_COLLISION` —— 主动让③"空间只增不减"去撞击"顺序存储的判满 = 容量用尽"，暴露"扩容必须搬迁（破坏 O(1)）"或"必须放弃循环复用（破坏③）"这一不可调和点，用相撞结果排除一种表示。
- `after_state`: 存储结构的候选集合被约束相撞缩小；"判满依赖容量"这一整类方案被排除，问题变成"在剩下的表示里如何同时满足复用与不归还"。
- `why`: 题面把三条要求并列写出且没有给任何提示 → 说明它们是**约束筛选器**而非实现细节；(1) 问"链式还是顺序"进一步确认筛选是本题第一步。
- `basis`: `pattern_recall`
- `basis_note`: **必须如实声明**：我对"2019 年这道队列题该选哪种存储结构"存在**模糊的真题记忆**，无法排除"排除顺序存储"这一结论部分来自回忆而非纯题面推理。按任务书要求，隐瞒比标注危险，故标 `pattern_recall`。

**predicted_second_transition**
- `before_state`: 表示已选定，但"复用"与"不归还"仍然冲突：常规做法复用即归还，而归还违反③。
- `operation`: `AUXILIARY_OBJECT` —— 引入一个与"逻辑队列"无关的辅助结构（已分配但当前空闲的空间池 / 让结点在队列内部循环复用），使"复用"变成"在自有空间内部周转"而不再需要归还系统。
- `after_state`: "空间复用"与"空间只增不减"被解耦：复用在内部池完成，占用总量单调不减；判空/判满退化为对该辅助结构的指针/计数关系，因而 O(1)。
- `why`: ③的"只增不减"只有在"空间不离开队列"时才成立 → 必须有一个承接"已用/未用"的中间对象；题面要求"定义判空和队满的条件"也说明需要一个可判读的中间状态。
- `basis`: `pattern_recall`
- `basis_note`: "循环单链表 / 空闲结点复用"是 408 队列设计题的常见套路。我无法从题面确定标准解用的是"结点回收进空闲链"还是"结点在队列内循环"，也无法排除"顺序循环队列 + 满则扩容但不释放旧空间"这一完全不同的路线。

**system_state**
（逻辑队列内容；队首/队尾位置指示；已分配空间总量）三元组。判空/判满判据是该状态的函数。

**resources**
- 已分配的存储空间（**单调不减**，不可归还）
- 时间（入队、出队各 O(1)，且**扩容动作也必须摊到 O(1)**）

**agents_or_components**
队列本身（无并发主体）；若引入空闲结构，则还有"空闲空间池"这一被动组件。

**invariants**
- 已分配空间总量单调不减
- 出队元素占用的空间可被后续入队再次使用
- 队空/队满判据可由当前指针/计数在 O(1) 内判定，且**不依赖"当前总容量是否用尽"**
- 队列的逻辑 FIFO 序不被空间复用打乱

**state_transition**
- `初始空 → 第一个元素入队 → 非空（且已分配空间不为零）`
- `入队（可能触发空间增长）`
- `出队（元素位置转为可复用，但空间不归还）`

**bottleneck**
"空间增长"与"空间复用"之间的接口：何时增长、增长后旧空间如何继续被复用。这是全题唯一可能破坏 O(1) 的环节，也是判满判据的落点。

**local_vs_global_effect**
局部地"出队后释放该结点"（一个很自然的局部动作）会让"占用空间只增不减"这一**全局不变量**失效；反过来，局部地"复用结点"要求全局的已分配空间不缩水。局部动作与全局约束在这里直接对撞。

**layer_interface**
抽象队列语义层（FIFO、队空/队满）→ 存储层（顺序数组 / 链结点 / 辅助空闲结构）。题面 (1) 问的正是这一接口选哪一侧。

**UNKNOWN**
1. "出队后空间可重复使用"与"空间只增不减"能否在**顺序存储**下同时满足，我无法从题面判定（取决于"不释放旧空间"是否算作"占用空间"）。这直接决定 (1) 的走向。
2. 题面未定义"队列占用空间"的计量口径（是当前分配的容量，还是包含已被复用位置的总量）→ 无法确定③的严格含义。

**uncertainty**
本题是我**最没把握**的一道。核心不确定是"空间只增不减"的计量口径：若它指"已向系统申请的总量不减"，则链式（不 `free`）与顺序（扩容不释放）都可行；若它指"物理地址范围只增不减"，则只有顺序扩容可行。我倾向"约束相撞排除顺序"，但这依赖我对"扩容必须搬迁"的默认假设——若标准解用的是"分段/链式块"，这个假设就不成立。已按纪律标 `pattern_recall`。

- 集线器：既不隔离冲突域也不隔离广播域；交换机：隔离冲突域、不隔离广播域；路由器：两者都隔离
- CSMA/CD：往返传播时延 ≤ 最小帧的发送时间（**此条来自机制记忆**）
- DHCP DISCOVER 为广播 ⇒ 目的 MAC 全 F，且默认不被路由器转发（除非配置中继）
- 802.11 帧的三个地址字段语义由该跳的"发送方 / 接收方 / 转发角色"决定，与以太网不同

**state_transition**
- `H4：无 IP → 发 DISCOVER（广播）→ 收 OFFER → 发 REQUEST → 收 ACK → 已配置`
- `帧：H4 →（设备 1/2）→ AP → … → H5，逐跳重封装，链路层地址逐跳改变`

**bottleneck**
- 冲突域的最大直径（由最小帧长与中继延迟共同决定）是本题的硬瓶颈。
- DHCP 部分的瓶颈是"**广播不被路由器转发**"这一域边界：它决定了 E0 能否收到报文 M。

**local_vs_global_effect**
- 把一个集线器换成交换机（局部设备替换）会改变整个冲突域的划分与距离约束（全局）。
- H4 的一次广播（局部动作）会泛洪到**整个广播域**（全局）；而正因为路由器不转发广播，泛洪在路由器处被截断。
- 交换机对未知单播泛洪（局部未知 → 全局流量）。

**layer_interface**
物理层（介质 / 中继延迟 / 最小帧长）→ 链路层（冲突域 / 帧地址 / 交换机与集线器行为）→ 网络层（IP / DHCP 广播 / 路由器边界）→ 802.11 帧格式层。

4. **H1–H5 的其余连接关系 —— UNKNOWN**（题面只给出两处域关系断言）。
