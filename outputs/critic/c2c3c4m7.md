## 专项三：C2 的三个 CANDIDATE_NEW_OPERATOR 是否真的无格可填（问题 3）

**总判定：三个候选全部成立，现有 37 个母算子确实无法表达"自指层级"。worker 没有硬贴。**
**其中 2 个候选的"为什么现有标签不够"论证成立，但它们的 `existing_operator_matches` 里的主算子却在做别的事——这是主算子错位，不是候选错位。**

### 逐个核验

#### ① `CANDIDATE_DUAL_ROLE_RESOURCE_SPLIT`（`C2-011`）——✅ 成立

- **worker 的论证**：`INFORMATION_AXIS_DECOMPOSITION` 只说"沿信息轴拆开"，不强调**两个计数视图必须守恒耦合**；
  `SPACE_AUGMENTATION` 只说"增加变量/维度"，不说明两个变量之间的守恒约束。
- **我的独立核验**：逐条比对 37 个母算子的定义（`OPERATOR_DEFINITIONS.md` §2）：
  - `AUXILIARY_OBJECT` = 引入**一个可指名的实体** → `pits` 与 `empty` 是两个信号量，都是实体 → **能覆盖一半**；
  - `INFORMATION_AXIS_DECOMPOSITION` = 按**信息维度**拆开 → 额度/库存确实是两条轴 → **能覆盖另一半**；
  - **没有任何标签表达 `pits + empty = 3` 这条守恒关系是"正确性证书"**。
  - **判定：worker 对。** "同一份物理资源在两个作用域下各有一个计数视图、且两视图之和守恒"确实是新结构。
- **但必须指出主算子错位**：`C2-011` 的 primary 是 **`STATE_REREPRESENTATION`**（"把过程重表示为流水线 + 有界缓冲"）。
  **"把流水线重表示为流水线"不是换表示。** 该条真正承重的动作恰恰是 worker 自己提的
  `CANDIDATE_DUAL_ROLE_RESOURCE_SPLIT`，而它被挂在 `possible_new_operator` 里、**没有出现在 primary 位**。
  **要求：`C2-011` 的 primary 改为该候选（或标 `UNKNOWN`），`STATE_REREPRESENTATION` 删除。**
- **另一处需要复核**：`C2-011` 的 `evidence_level` 标 E2，但 `confidence` 是 medium，
  且 `notes` 明说"把该题重标定为「有界缓冲 + 额度守恒(pits+empty=3)」是本 worker 的归纳"。
  **按 SPEC §6.1，`evidence_level` 与 `confidence` 是两个独立的轴，这样组合不算矛盾**——
  材料确实明说了"有界"（"不允许同时存在 4 个未被乙使用的树坑"），只是没说"守恒"。
  **判定：E2 保留，但需在 notes 写清 E2 覆盖的是"有界"这一层，"守恒"这一层是 worker 归纳。**

#### ② `CANDIDATE_SELF_APPLICATION_RECURSION`（`C2-013`）——✅ 成立，且有讲义原话支撑

- **结构**：页表要消除地址空间的离散性，自己却要求连续且全量常驻 → 把"分页 + 按需调入"**再施加到页表自身**。
- **讲义原话（我回源核验，`第03章_内存管理.md` L354）**：
  「不难发现，**这一方案与最初引入页表以解决进程地址空间离散分配的思路如出一辙**：本质上就是为已离散化的页表再建立一层页表，称为外层页表（或页目录）。」
  **材料自己就把这识别为"同一手段的重复"** —— 这是教科书级的 E2 证据。
- **现有标签为何不够（我逐条试填）**：
  - `SPACE_AUGMENTATION`：只说明"增加了维度"，**不表达"新加的维度就是把原手段再施加到原结构自身"**；
  - `SELF_IMPROVING_CLOSURE`：定义是"构造一个**自我改进/自我闭合**的过程（迭代收敛、逐步收紧）"。
    页表分级**不收敛、不改进**——层级数由地址位数与页大小的量级比**一次定死**（`2^20 / 2^10 = 2^10` 个页表页）。
    **我实测确认：`SELF_IMPROVING_CLOSURE` 覆盖不了。**
  - `STATE_REREPRESENTATION`：只说"换了表示"，不表达"同一个手段被递归施加"。
  - **判定：worker 对。确实无格可填。**
- **唯一的保留意见**：该候选在 C2 只出现 1 次（worker 自己也标"1（本 worker 材料内）"）。
  按 SPEC §5，E3 才值得进入稳定 ontology，**单例候选应挂"待聚合判定"**，不宜直接晋升为正式算子。
  但**"是否单例"与"是否有格可填"是两个问题**——前者是产量问题，后者是语义问题。**后者已经答清楚。**

#### ③ `CANDIDATE_SELF_REFERENTIAL_LOCALIZATION`（`C2-014`）——✅ 成立，但**证据等级与主算子都需要处理**

- **结构**：要被写入的页表项**自身就是虚拟地址**，必须经页表翻译才能得到物理地址 →
  **定位工具就是被定位对象的一部分**。
- **现有标签为何不够**：所有标签都假定"被定位对象"与"用于定位的机构"是分离的。
  - `STATE_REREPRESENTATION`：C2-014 的 primary 就是它（"把页表也表示为占据虚拟地址空间的对象，
    建立'虚拟表的虚拟视图'与'物理视图'两套坐标"）——**它描述的是"页表有两个视图"，
    不是"定位页表项时页表自身也在被定位对象集合里"**。这两件事不同：前者是表示，后者是依赖。
  - `SPACE_AUGMENTATION`：不涉及定位依赖。
  - **判定：worker 对。确实无格可填。**
- **但两条必须整改**：
  1. **主算子错位**：`STATE_REREPRESENTATION` 挂在 primary，而它描述的不是本题的承重动作
     （承重动作 = "定位页表项时页表自身也要被翻译"这一依赖，即候选本身）。**要求：primary 改为该候选或标 `UNKNOWN`。**
  2. **候选的证据基础为零，worker 已如实说明**：`evidence_level: E1`、`confidence: medium`，
     `notes` 写「原解析只机械执行了"页表项虚拟地址 = 页表起始虚拟地址 + 页号×4"，**没有把"页表自己也要被翻译"作为理由说出来**」。
     **这是 SPEC 禁止 4 的正面执行（"无法自然解释的标 UNKNOWN，不要硬贴"）**，但它也意味着
     **这个候选算子的定义是 worker 从解答反推的，不是材料陈述的**。建议：候选保留，但标注
     `evidence_basis: worker_inferred (E1)`，不要与 `C2-013` 那个"有讲义原话支撑"的候选同等对待。

### 关键判定：两个"自指"候选应**合并**还是**保持两个**？

**我的判定：保持两个，不应合并。但必须补一条共用前缀说明。**

理由（两条候选的操作含义不同，且这一点是**可检验的**）：

| | `CANDIDATE_SELF_APPLICATION_RECURSION`（C2-013） | `CANDIDATE_SELF_REFERENTIAL_LOCALIZATION`（C2-014） |
|---|---|---|
| 自指的类型 | **自施加**：为解决 P 而引入的手段 S 自身又有 P，于是把 S 再施加到 S 上 | **自包含**：用于定位/翻译的机构本身属于被定位/翻译的对象集合 |
| **可预测的后果**（这是区分的关键） | 层级数由**量级比**决定（C2-013：`2^20/2^10=2^10` 个页表页 → 外层页表恰好一页 → 定死为 2 级） | 定位必须**分两步**，且两步之间需确认"机构本身是否已就位"（页表页是否已在内存） |
| 失效模式 | 层级数算错 / 漏掉"页表页也占空间"这一项 | 只算一次翻译 → 用页表的虚拟地址当物理地址 |
| 可迁移去向 | 多级索引分配（C2-019 已实证同构）、B+ 树内部节点、目录层级 | TLB 缺失 vs 缺页（C3-010/C3-011）、自举编译器、quine |

**两条的"自指"是同一个词，但一个是"递归"、一个是"自包含"，后果与失效模式完全不同。合并会丢掉"层级数由量级比决定"这一可预测结论。**

**但建议补一条共用前缀说明**：在 `OPERATOR_DEFINITIONS.md` 中新增一节「自指类结构（self-reference family）」，
收录这两个候选，并给出一条分界问句：
> **"被重复施加的是同一个**手段**（→ 自施加），还是同一个**对象集合**（→ 自包含）？"**

**另一个必须回答的问题（任务书问的）：`STATE_REREPRESENTATION` 或 `SPACE_AUGMENTATION` 够用吗？**
**答：不够用，但理由不是"它们太窄"，而是"它们被用在了错误的位置"。**
两条的主算子都挂了 `STATE_REREPRESENTATION`，而它描述的**都是表示层的次要观察**（"页表有两个视图"），
**不是承重动作**（"手段递归"/"定位自包含"）。也就是说：
**候选是对的，primary 是错的——这两件事必须分开报，否则会被误读为"worker 硬贴候选"。**
