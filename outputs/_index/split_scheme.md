## 0. 判定顺序（`_protocol/OPERATOR_DEFINITIONS.md` §0）

不要先想"这题用了什么方法"，而要按顺序问：

```
1. 这一步改变了问题的对象/表示吗？          → STATE_REREPRESENTATION
2. 还是只把注意力限制到一个子集/切片上？      → RESTRICT_SLICE
3. 还是引入了一个原本不存在的新对象？         → AUXILIARY_OBJECT
4. 还是把某个量拆成互不耦合的块？            → INVARIANT_BLOCK_DECOMPOSITION
5. 还是把不可见的自由度商掉？                → QUOTIENT_KERNEL
6. 还是把多个约束/信息合并成一条？            → EXACT_ELIMINATION
7. 以上都不是，只是估计/试算/探边界？          → PROBE 家族
```

**判据的核心是"这一步之后，问题的对象变了没有"，而不是"这一步用了什么工具"。**

### 0.1 `STATE_REREPRESENTATION` vs `RESTRICT_SLICE`（§1.1）
- `STATE_REREPRESENTATION`：**对象本身换了表示**，换表示后**整个问题都在新表示下讨论**。
- `RESTRICT_SLICE`：**对象不变，只把注意力限制到一个子集**，切片之外的部分被暂时搁置但没有被重新表示。
- **分界问句**：切片之外的东西**还在不在问题里**？在 → `RESTRICT_SLICE`；不在（已被新表示吸收）→ `STATE_REREPRESENTATION`。

## 2. `RESTRICT_SLICE` 子算子（`unexplained_cases.md` §4.2，4 类 + null）

| 子算子 | 定义 | 代表实例 |
|---|---|---|
| `REGION_SPLIT` | 把积分区域/定义域/样本空间按奇点或符号拆成若干段，每段内机制唯一 | `M3-003`、`M3-010`、`M8-013`、`M8-019`、`C2-001` |
| `SUBSET_FILTER` | 对象不变，只把注意力限制到候选子集/一段/一个点（= 原义） | `C1-012`、`M2-014`、`M3-006`、`M6-004`、`M7-021` |
| `DIMENSION_REDUCTION` | 沿某个组合量/轴/曲线/流形把高维对象限制为低维，再用低维工具 | `M4-002`、`M4-003`、`M4-009`、`M7-004`、`M7-018` |
| `CONSTANT_FIXING` | 用初值/边值/单调性条件在**解族**上取切片，把通解中的自由常数定下来 | `M5-001`、`M5-005`、`M5-007`、`M5-008`、`M5-009`、`M5-011`、`M5-014`、`M5-017` |
| `null` | **不属本算子**：做差归约 / 机械代入 / 定义验证 / 反例核对 | `M3-013`、`M3-020`、`M4-008`、`M4-019` |
| `UNCLASSIFIED` | 所有子类都装不下（必须写明理由） | — |

**`SUBSET_FILTER` vs `CONSTANT_FIXING` 的客观判据**：
`SUBSET_FILTER` 限制的是**空间/集合**（"只看这几个选项""只看这一段"）；
`CONSTANT_FIXING` 限制的是**解族中的参数**——**被限制的对象是"一族解"，不是"一个集合"**。
判据是数得出来的：**"被切片的是空间还是解族？"**

> `M5-018` 的 worker 自己驳回了 `RESTRICT_SLICE`（"限制是解流形自身的内蕴像，并非主动选择"），
> §4.2 采信该驳回 → 若当前数据里 `M5-018` 仍挂着 `RESTRICT_SLICE`，判 `null` 并写明。

## 3. `BAD_REPRESENTATION_LOCK_IN`（anti）子类（`unexplained_cases.md` §4.4，5 桶 + 1 移出）

> ⚠️ 这个标签**实测是兜底标签**：147 次用法里绝大多数与"表示"无关。
> 八条实例、八种不同失败机制、同一个标签。

| `sub_failure_type` | 定义 | 报告计数 |
|---|---|---:|
| `REPRESENTATION_LOCK_IN` | 在**已知不适用的标准形/表示**下继续硬算；失效机制是"该表示的**适用前提被破坏**" | 76（50.7%） |
| `STRUCTURE_MISREAD` | 对对象的**结构属性**判断错误：类型（离散/连续/混合）、身份（系数/取值）、量级（次序统计量/均值） | 33（22.0%） |
| `EXPENSIVE_BUT_VALID` ⭐ | 路线**正确**，但代价过高/过于繁琐；**方法本身适用** | 29（19.3%） |
| `CONSTRAINT_VIOLATION` | 直接违反题面**明写**的硬约束（复杂度、空间、"不许改动"）。**C1 专用**（全语料仅 3.3%） | 5（3.3%） |
| `NO_ABSTRACTION` | 路线正确但缺统一抽象，导致代码分支或无法给出离线判据 | 3（2.0%） |
| `ROUTE_IS_VALID` | **根本不是错路**，应从 `naive_routes` 移出 | 3（2.0%） |
| `UNCLASSIFIED` | 5 桶都装不下（必须写明理由） | — |

**`EXPENSIVE_BUT_VALID` vs `REPRESENTATION_LOCK_IN` 的判据（§4.4 分歧 1，最重要）**：
> `REPRESENTATION_LOCK_IN` 的失效机制是**"该表示/标准形的适用前提被破坏"**；
> `EXPENSIVE_BUT_VALID` 的失效机制是**"太贵"**——方法本身适用。
> 前者要教"这个标准形的前提不成立"，后者要教"这条路的代价估算"。
> 典型代价语言："计算量爆炸"、"计算量极大"、"开销较大"、"越算越繁"、"计算量翻倍"。
> **注意**：有代价语言**不等于**就是 `EXPENSIVE_BUT_VALID`；若 `why_fails` 同时指出
> "公式的适用前提被破坏"（例如"右端对 y 不是线性，p(x)、q(x) 根本写不出来"），
> 则失效机制是前提被破坏 → `REPRESENTATION_LOCK_IN`。

**`STRUCTURE_MISREAD` 的判据（§4.4 分歧 3）**：
对**对象的结构属性**判断错误，不是"用错了公式"，而是**把对象看错了**：
- 类型误判：`M8-005` 看到 Y 是离散的，就认定 Z 是离散型；`M8-013` 把 `Y=[X]+X` 当成 X 的光滑函数
- 身份误判：`M8-015` 看到 0.3 与 0.7 两个系数，就认为 `E(X)=0.3+0.7=1`（把混合权重当成取值）
- 记号误读：`M8-008` 把 `(1/n)ΣX_i²` 误读为 `((1/n)ΣX_i)²`；`M7-001` 把 `A_ij` 当成第 i 行元素进入计算
- 角色误判：`C2-001` 把"等待"当成一个状态；`C2-008` 把 value 的负值当成"资源欠账"

**`REPRESENTATION_LOCK_IN` 的判据**：
在**已知不适用的标准形/表示**下继续硬算。典型：套线性方程公式但方程非线性、
套特征方程但系数含 x、套分布函数法但函数有跳跃（反函数不存在）、
套比值法但级数不是幂级数、用满指令编码却还想要扩展入口。
