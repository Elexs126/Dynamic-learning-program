# 算子实际用法证据（用于撰写算子定义）

由现有 Episode 的 xisting_operator_matches[].why 与主算子的 	rigger_signals 汇总。

**用途**：盲测预测者指出 EPISODE_SPEC 只给了裸标签、没有定义，导致标签无法一致使用。
本文件提供**实际用法**作为定义的依据。

## STATE_REREPRESENTATION  (n=79)

**worker 给出的理由（样本）**

- C1-002 — 空表由"头指针为 NULL"重表示为"头结点 next 为 NULL"，两种状态归并为一
- C1-003 — 把"删除 p"重新表示为"覆盖 p 的内容 + 删除 p 的后继"，改变了被删对象的身份
- C1-005 — 把"能否由栈得到"的过程性描述重表示为序列上的"312 模式"
- C1-006 — 把队列重新表示为循环单链表 + 一个保留空闲结点，改变了队空/队满的判定方式
- C1-007 — 逆置改变了后半段的表示方向，把"从尾向前取"变成"从头向后取"
- C1-009 — 线索化把"父子关系结构"补充为"父子关系 + 某种遍历序的前驱后继结构"
- C1-010 — 把多叉树重新表示为二叉链表（左孩子-右兄弟），使树与二叉树共享同一物理结构
- C1-023 — 用取模把线性数组重新表示为环，改变了"队满"这一状态的判定方式

**该算子作主动作时的 trigger（样本）**

- C1-003 — 只给了指向待删结点的指针，没有头指针 → 说明无法从 p 反向访问前驱，常规删除路径不可用
- C1-003 — 题目要求 O(1) → 说明不允许遍历找前驱
- C1-005 — 要求判断"能否由栈得到" → 说明要给出一组序列上的充要条件，而不是逐例模拟
- C1-005 — 入栈顺序固定为 1..n → 说明"数的大小"与"入栈先后"完全一致，可以用大小关系替代时间关系
- C1-006 — 要求"出队后空间可复用" → 说明不能真正释放结点，必须保留在链上

- C1-018 — 把显式记录的切片限制在某一侧（出边或边存在性），而不是试图同时记录两侧
- C1-021 — 把问题限制在"大小为 k 的候选容器"这一切片上，而不是处理全部 n 个元素的次序

**该算子作主动作时的 trigger（样本）**

- C1-012 — 相同关键字集合可生成高度差异极大的二叉排序树 → 说明必须为树形引入额外的约束
- C1-012 — 查找代价 = 树高 → 说明约束应直接作用在"高度"这一量上
- C1-018 — "查邻接点"与"判断两点是否有边"的代价在两种表示下恰好相反 → 说明结构选择等价于操作代价的取舍

**worker 给出的理由（样本）**

- M2-013 — (1) 的结论 f(ξ)=1-ξ 恰好等价于 ξ+f(ξ)-f(0)=1，即把 [0,1] 分成两段后“两段高度之和为 1” → (1) 的作用是提供一个能控制分段比例的点
