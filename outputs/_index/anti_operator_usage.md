# anti-operator（failure_type）实际用法证据

由 `anti_operator_usage.py` 从全部 Episode 的 `naive_routes` 汇总。

## 用途

母算子曾有"只有裸标签、没有定义"的问题（盲测预测者实测指出，已由
`OPERATOR_DEFINITIONS.md` 修复）。**anti-operator 从未做过同样的检查。**

它的集中度更低（top3 45.7% vs 母算子 90.4%），值得核实：
这是**真的更一致**，还是**只是标签更多、每个用得更少**？

## 各标签的实际用法（判断是否一致使用）

> 读法：若同一标签下的"为什么差"高度相似 → 定义清晰、使用一致；
> 若五花八门 → 该标签是筐，需要拆分或补定义。

### `BAD_REPRESENTATION_LOCK_IN`（150 次）

- `C1-001` — **路线**：把哨兵单元也当成数据元素统计进表长与 ASL
  - 为什么差：哨兵是每次查找临时写入的，不是表的一部分；把它计入表长会同时算错 ASL 的分母与失败比较次数
- `C1-002` — **路线**：为"首部插入/删除"单独写一个 if 分支去改头指针
  - 为什么差：每类操作都要维护两条代码路径，空表还要第三次分支；分支越多越容易漏改，且无法把操作写成统一的过程
- `C1-003` — **路线**：从头遍历找 p 的前驱，再按常规方式删除 p
  - 为什么差：时间复杂度 O(n)，不满足 O(1) 要求；而且题目根本没有给出头指针，遍历起点不存在
- `C1-004` — **路线**：先把链表逆置，再正着数第 k 个
  - 为什么差：题目明确要求"不改变链表"，逆置破坏了链表结构；即使允许，也要 O(n) 额外遍历
- `C1-005` — **路线**：只检查"每个元素出栈时栈顶是否是它"
  - 为什么差：这仍是过程性模拟，需要同时追踪入栈指针与栈内容；没有给出可离线检验的模式
- `C1-006` — **路线**：用顺序循环队列（取模）实现
  - 为什么差：顺序存储的容量是预先固定的，无法满足"入队时允许增加占用空间"与"占用空间只增不减"
- `C1-007` — **路线**：把链表复制到数组后按下标重排
  - 为什么差：违反 O(1) 空间；且复制本身 O(n) 额外空间
- `C1-009` — **路线**：为每个结点增加两个额外的 prev/next 指针域
  - 为什么差：每个结点多两个指针域，空间开销 O(n)；而 n+1 个空链域本来就是空闲的，属于重复投入

### `PROXY_OBJECTIVE_DRIFT`（64 次）

- `C1-003` — **路线**：把 p 的 data 直接清空当作删除
  - 为什么差：结点仍在链上，长度不变，后续遍历会读到空内容，语义错误
- `C1-006` — **路线**：用 front==rear 同时表示队空与队满，再靠额外计数器区分
  - 为什么差：题目给出的是"参考循环队列牺牲一个单元来判断"的约定；引入计数器虽然可行，但改变了题目要求的状态表示，且题目要求画出初始状态与判定条件
- `C1-012` — **路线**：把平衡因子写成左右子树结点数之差
  - 为什么差：AVL 的平衡因子定义是"左右子树高度差"；用结点数会给出不同的不变量，无法保证树高为 O(log n)
- `C1-013` — **路线**：只保证根到叶的最长路径不超过最短路径的 2 倍，直接按这一条件构造
  - 为什么差：该结论是由五条性质推出的，不是可局部检查的规则；构造时必须靠颜色与黑高这些可局部判定的性质
- `C1-016` — **路线**：只看平均时间复杂度，一律选快排
  - 为什么差：若要求稳定性则快排不满足；若记录本身很大，快排的频繁交换会带来高昂的移动开销；若初始已基本有序，快排反而退化到最坏情况
- `C1-019` — **路线**：把"关键路径"理解为"边数最多的路径"
  - 为什么差：关键路径是权值之和最大的路径，不是边数最多的路径；真题明确"关键路径是指权值之和最大而非边数最多的路径"
- `C1-021` — **路线**：对全部 n 个数排序后取前 10 个
  - 为什么差：需要 O(n log n) 次比较，而问题只要求 k=10 个最小元素；计算了远多于所需的次序信息
- `C1-022` — **路线**：每次合并时选择长度最接近的两个表
  - 为什么差：合并代价是 m+n−1，与两表长度之差的绝对值无关；均衡并不减少总代价，真正决定代价的是长度被计入的次数

### `PROMISING_AS_PROVED`（64 次）

- `C2-003` — **路线**：把 count 当成普通变量直接自增自减
  - 为什么差：count++ 与 count-- 都是读-改-写三步，两个读者交错时可能都读到 0，导致写者被放进文件或 P(rw) 被漏掉，读者与写者同时访问文件
- `C2-005` — **路线**：把安全状态等同于不会死锁，或把不安全状态等同于已死锁
  - 为什么差：安全 ⇒ 一定不死锁；不安全 ⇏ 一定死锁（只是可能）。弄反蕴含方向会导致对系统状态的误判
- `C2-006` — **路线**：见到资源分配图有环就判定死锁
  - 为什么差：当某类资源有多个实例时，环外实例的释放可打破等待环，系统并未死锁；直接判死锁会导致误报与不必要的进程终止
- `C2-007` — **路线**：用普通函数 newSwap(&key,&lock) 代替硬件 swap 指令
  - 为什么差：newSwap() 执行时对共享变量 lock 既有读操作又有写操作，多个线程可并发执行该函数，读与写之间可被切换，因此无法保证原子交换，会导致并发线程同时进入临界区
- `C2-014` — **路线**：把页表项的物理地址直接写成 页表起始物理地址 + 页号×4 而不再检查该页表页是否在内存
  - 为什么差：该前提只在页表已全部驻留内存时成立；若页表本身也按需分页，则必须先确认对应页表页在内存，否则计算出的物理地址指向未装载区域
- `C2-024` — **路线**：用 SCAN 消除饥饿后认为公平性已解决
  - 为什么差：SCAN 对最近扫描过的区域不公平，中间区域的响应延迟较大；C-SCAN 需把回扫改为非服务性的快速跳转才能缓解
- `C2-025` — **路线**：用混合内核兼顾两者而不承认代价
  - 为什么差：把高频服务移入内核会使微内核的容量明显增大，可靠性与安全性收益相应被削弱；收益与代价只是被重新分配，并未消失
- `C3-015` — **路线**：把 RISC 理解为"指令越少越好"或"性能必然更高"
  - 为什么差：RISC 简化了硬件，但把"用多条简单指令组合实现复杂功能"的负担转移给了编译器；讲义明确指出 RISC "高度依赖编译器优化"，且现实中 x86 凭借软件生态仍占主流。把 RISC 当成无条件更优会解释不了这些事实。

### `OVER_DECOUPLING`（58 次）

- `C1-004` — **路线**：用大小与 k 有关的辅助数组保存最近 k 个结点
  - 为什么差：评分说明规定"使用了大小与 k 有关的辅助数组……最高给 10 分"，空间复杂度不达标
- `C1-007` — **路线**：把链表结点依次压入栈，再交替弹出
  - 为什么差：违反 O(1) 空间要求（题目明确"题目要求空间复杂度为 O(1)，不能借助栈"）
- `C1-010` — **路线**：只用孩子表示法（每个结点挂一条孩子链表）
  - 为什么差：查某结点的双亲要遍历所有孩子链表检查是否包含该结点，代价 O(n) 以上
- `C1-018` — **路线**：一律用邻接表
  - 为什么差：判断两点间是否有边需要线性查找边表；求有向图的入度需要遍历所有顶点的边表
- `C2-001` — **路线**：认为所有系统调用都会让进程阻塞
  - 为什么差：只有需要等待外部事件的操作才阻塞；很多系统调用立即返回，进程仍在运行态
- `C2-003` — **路线**：给整个文件一把互斥锁，读者也串行化
  - 为什么差：满足了写者排他，却违反'允许多个读者同时读'的题目要求，把并发读降级为串行，吞吐量按读者数线性下降
- `C2-006` — **路线**：认为四个必要条件彼此独立，可分别单独检查
  - 为什么差：它们是'同时满足'的合取条件，破坏任意一条即可；把'循环等待'当成与死锁同义，等于把合取条件误当成等价定义
- `C2-009` — **路线**：用一个全局信号量表示'上一个程序段完成'
  - 为什么差：S1 完成后需同时通知 S2 与 S3，S6 需等待三个前驱；单信号量的 V/P 会丢失通知或被误消费，导致某些段提前执行或永久阻塞

### `PREMATURE_APPROXIMATION`（55 次）

- `C1-005` — **路线**：只看序列是否"看起来像后进先出"（比如相邻两数是否递减）
  - 为什么差：合法序列大量出现局部递增（如 2,3,1），局部观察无法判定；必须看到三元组跨度的约束
- `C1-008` — **路线**：只做路径压缩，不做按大小合并
  - 为什么差：压缩只作用于被访问过的路径；未访问的分支仍可能很深，且合并时仍可能反复造出深树
- `C1-011` — **路线**：每次随机选两棵树合并
  - 为什么差：合并次序直接决定 WPL，随机选择无法保证最优；例中三种树形的 WPL 分别为 36、46、35
- `C1-013` — **路线**：完全放弃平衡，用普通二叉排序树
  - 为什么差：树可能退化为单支树，查找退化为 O(n)，失去二叉排序树的动态查找优势
- `C1-014` — **路线**：插入时直接往终端结点里加关键字，不设上限
  - 为什么差：结点会无限膨胀，无法与磁盘块大小匹配；结点内查找退化为线性扫描，且"一次 I/O 读入一个结点"的前提失效
- `C1-015` — **路线**：以为装填因子 α<1 就能避免碰撞
  - 为什么差：α<1 只表示还有空位，冲突由散列函数的多对一性质决定，与是否装满无关；α 影响的是冲突的期望次数
- `C1-016` — **路线**：认为基数排序时间接近线性就一定最快
  - 为什么差：基数排序的实际效率受限于关键字结构与平台支持，通用性较弱；对实数字关键字无法直接使用（真题中"关键字为实数"就排除了基数排序）
- `C1-017` — **路线**：无限增大 k 以进一步减少 I/O
  - 为什么差：归并路数 k 并非越大越好：增大 k 需要增加输入缓冲区数量，若总内存固定则每个缓冲区容量减小，每趟归并的外存读/写次数增加，k 过大时总体 I/O 反而可能增加

### `PREMATURE_INFORMATION_LOSS`（46 次）

- `C1-002` — **路线**：用"头指针是否为 NULL"来判断空表
  - 为什么差：一旦引入头结点，头指针恒非空，判空条件必须改成 head->next==NULL；若两种约定混用，空表与非空表会走错分支
- `C1-003` — **路线**：直接 free(p) 或 p = p->next
  - 为什么差：free(p) 只归还存储空间，前驱的 next 仍指向已释放的位置，链断裂并产生悬挂指针；p=p->next 只改了局部变量，链上什么都没变
- `C1-006` — **路线**：用普通链式队列，出队时 free 掉队头结点
  - 为什么差：空间被真正释放，违反"出队后元素所占空间可重复使用、整个队列占用空间只增不减"
- `C1-009` — **路线**：让空指针直接指向线索，不加标志域
  - 为什么差：同一个指针域既可能指向孩子又可能指向线索，遍历时无法区分，必须额外判断（或引入全局约定），语义不可判定
- `C1-015` — **路线**：用开放定址法并在删除时直接物理删除该元素
  - 为什么差：会截断其他同义词的查找路径，导致查找失败；正确做法是设置删除标记做逻辑删除（副作用是表看似已满但实际有很多位置未用）
- `C1-023` — **路线**：用 front==rear 同时表示队空与队满
  - 为什么差：两种状态不可区分，队列的状态判定失效；必须牺牲一个单元（或引入计数器）来消除歧义
- `C1-024` — **路线**：用 visited 同时表示"访问过"和"在当前递归路径上"
  - 为什么差：检测环需要区分"已完全访问"与"仍在当前路径上"两种状态（否则无法识别回溯边）；只用一维 visited 会把二者混淆
- `C2-009` — **路线**：给汇合点 S6 只放一个 P 操作
  - 为什么差：S6 需要 S3、S4、S5 全部完成；只等一个会在另外两个尚未完成时提前执行 S6，违反偏序约束

### `TARGET_DRIFT`（46 次）

- `C1-011` — **路线**：把权值最大的结点放在最深层，认为"重要的放近处"要靠对称平衡
  - 为什么差：完全平衡的树让所有叶结点深度相同，大权值结点被迫也占一个较深的层，WPL 反而更大（讲义例中 WPL=36）
- `C1-013` — **路线**：继续用 AVL，接受频繁调整
  - 为什么差：讲义明确指出"在插入和删除操作后，会非常频繁地调整全树的整体拓扑结构，代价较大"；插入删除频繁的场景下维护成本超过查找收益
- `C1-016` — **路线**：认为稳定性是算法优劣的衡量指标
  - 为什么差：讲义明确"稳定性并不能用来衡量算法的优劣，而只是描述其性质之一"；当关键字互不重复时排序结果唯一，稳定性无关紧要
- `C1-017` — **路线**：为了避免内部开销增长，干脆把 k 固定为较小值
  - 为什么差：S = ⌈log_k r⌉ 随 k 减小而增大，磁盘 I/O 次数上升；在 I/O 主导的外部排序中得不偿失
- `C1-019` — **路线**：把关键活动压缩得越多越好
  - 为什么差：不能任意缩短：一旦过度缩短，原关键路径的长度可能小于其他路径，从而引发关键路径转移；此时继续压缩该活动，工程总工期已由新的最长路径决定，不再受其影响
- `C1-020` — **路线**：只检查图中是否有环（有环则无拓扑序列）
  - 为什么差：有环 ⇒ 不存在拓扑序列，与"唯一"是两个不同的问题；无环时仍可能有多条拓扑序列
- `C1-022` — **路线**：按表的长短顺序依次合并（如先把最长的两表合并）
  - 为什么差：把长表先合并会让它的长度在后续每次合并中反复计入，总比较次数变大；与"最短优先"的结论相反
- `C2-010` — **路线**：第(3)问再加一个表示'B 非空'的信号量
  - 为什么差：沿用会引入无用的同步约束：第(3)问中 B 初始就非空且两进程都只执行 C3，不需要任何'等待 B 变满'的同步，只需一把互斥锁即可；多加信号量违背'尽可能少'的要求

### `RECOMPUTE_WHOLE_FOR_LOCAL_CHANGE`（35 次）

- `C1-001` — **路线**：把越界判断写进循环条件（while i>=1 && ST.elem[i]!=key）
  - 为什么差：每一轮循环都要多做一次下标比较，n 次循环就多 n 次比较；而且查找失败路径上的判断次数与成功路径不一致，代码里出现两处循环条件分支
- `C1-004` — **路线**：第一趟遍历求表长 n，第二趟走到第 n-k+1 个结点
  - 为什么差：需要两趟扫描；评分说明规定"采用两遍或多遍扫描才能得到正确结果的，最高给 10 分"（满分 15 分）
- `C1-007` — **路线**：每次需要"倒数第 i 个"时就遍历一遍链表去取
  - 为什么差：每次取都要 O(n) 遍历，总计 O(n²)，时间效率不可接受
- `C1-008` — **路线**：每次 Find 后重新构建整棵树
  - 为什么差：重建代价 O(n)，远高于压缩路径的 O(路径长度)；把"局部改路径"升级为"全局重建"
- `C1-009` — **路线**：继续用递归或显式栈完成遍历
  - 为什么差：需要 O(h) 辅助空间，且每次遍历都要重建这份"前驱记忆"；栈的存在使遍历无法在 O(1) 空间内完成
- `C1-012` — **路线**：每次插入后重新构建一棵完全平衡的树
  - 为什么差：重建代价 O(n)，插入变成 O(n)；而旋转只需 O(1) 次指针操作
- `C1-017` — **路线**：用普通 k 路归并，每次线性扫描 k 个元素找最小
  - 为什么差：每次选择 k−1 次比较，每趟 n 个元素共 (n−1)(k−1) 次比较；S 趟总比较次数约 ⌈log2 r⌉(n−1)(k−1)/⌈log2 k⌉，(k−1)/log2 k 随 k 增大而增大，内部归并时间随之增长
- `C1-018` — **路线**：用邻接表表示无向图，接受每条边存两次
  - 为什么差：同一条无向边用两个结点表示，在"判断两顶点间是否有边"时需分别遍历两个顶点的边表；邻接多重表通过将每条边仅用一个结点表示，从而在判断边时只需遍历一次

### `MISSING_SHARED_WITNESS`（26 次）

- `C1-019` — **路线**：找到一条关键路径，加快其上任一关键活动即可缩短工期
  - 为什么差：讲义明确指出"当存在多条关键路径时，仅提高其中某一条路径上的关键活动速度，并不能缩短整个工程的工期"；只有加快同时出现在所有关键路径上的公共关键活动才有效
- `C4-017` — **路线**：只依赖「发送前侦听信道空闲」来判断能否发送
  - 为什么差：隐蔽站 A 与 B 可能同时侦听到空闲并同时发送，在 AP 处冲突；双方都以为自己安全
- `M1-014` — **路线**：沿一条路径 $x_n=1/((2n+1/2)\pi)$ 算出 $f\to\infty$，据此选 (A)
  - 为什么差：单条路径的收敛不能决定原极限；必须至少两条路径行为不同才能否定存在性
- `M2-001` — **路线**：直接对 f 在 [a,b] 上用罗尔定理或拉格朗日中值定理
  - 为什么差：罗尔要求两个相等的函数值，题面只给了一个 f(a)=0；拉格朗日给出 f'(η)=f(b)/(b-a)，与目标式 f(ξ)=(b-ξ)f'(ξ)/a 形式不同，无法对齐
- `M2-002` — **路线**：直接对 f 用罗尔定理得到 f'(ξ)=0，然后声称 f f''+(f')² 在该点为零
  - 为什么差：罗尔给出的是 f'(ξ)=0，代入后得到 f(ξ)f''(ξ)，仍含未知的 f''(ξ)，不等于 0；而且这样最多得到 1 个点，达不到“两个不同实根”
- `M2-004` — **路线**：对 f 在 [0,2] 上用拉格朗日中值定理，再想办法接 f(3)
  - 为什么差：拉格朗日给出 f'(η)=(f(2)-f(0))/2，与 f(1) 无关，三个值里的中间那个完全用不上；且拿不到 f'(ξ)=0
- `M2-005` — **路线**：对 f 用两次拉格朗日中值定理，试图让两个中值点相等
  - 为什么差：两次拉格朗日给出的中值点一般不同，无法保证 ξ1=ξ2，也就拿不到 f''(ξ)=0；缺一个共享的等值条件
- `M2-007` — **路线**：构造 F=f²/2 后对它用罗尔定理
  - 为什么差：罗尔要求 F 有两个相等的函数值，题面没有；强行用罗尔会得到 F'(ξ)=0，即 f(ξ)f'(ξ)=0，与要证的 >0 不符

### `LOCAL_REPAIR_GLOBAL_ERROR`（24 次）

- `C1-008` — **路线**：Union 时总是把 Root2 挂到 Root1 下面
  - 为什么差：连续的"大挂小"会造出深度 n 的链，Find 最坏 O(n)；单次 Union 的 O(1) 把代价转嫁给了未来所有 Find

  - 为什么差：父结点自身也有下限；借位必须"父子换位"（父关键字下移、兄弟关键字上移）才能同时维持两侧区间划分，直接借会破坏有序性
- `C1-015` — **路线**：用线性探测，冲突就一直往后找
  - 为什么差：线性探测容易引发"聚集（堆积）"：原本映射到地址 i 的同义词被存入 i+1，本应存入 i+1 的元素被迫占用 i+2，大量元素在相邻地址堆积，显著降低查找效率
- `C2-002` — **路线**：按直觉先加锁再检查资源：P(mutex); P(empty); ...
  - 为什么差：缓冲区满（empty=0）时生产者持锁阻塞在 P(empty)；消费者要取产品需先进临界区，而 mutex 已被生产者持有，消费者也阻塞，双方互等，形成死锁。这是典型的局部正确、全局错误
- `C2-007` — **路线**：进入区用 if 而不是 while
  - 为什么差：若锁已被占用，进程应当继续尝试而不是直接跳过或直接进入；用 if 会在锁不可用时放行或误判，退出区若把 lock 置为 TRUE 则锁永不释放
- `C2-012` — **路线**：把所有'回到就绪队列'都按时间片用处理，优先级一律减 1
  - 为什么差：P2 在 20 ms 被 P4 抢占时优先级本应保持 4，若减为 3 则后续 P2 与 P3、P1 的相对次序全部改变，调度次数与首次调度时刻随之全错
- `C2-015` — **路线**：频繁使用紧凑技术把空闲块合并
  - 为什么差：紧凑要求系统支持动态重定位，且需要移动进程，开销较大；把它当作常规手段会让系统长期处于高开销状态
- `C2-017` — **路线**：看到 CPU 利用率低就增加多道程序度
  - 为什么差：抖动时 CPU 利用率低的原因是进程都在等 I/O，不是 CPU 空闲；增加进程会加剧页框竞争，使页面置换更频繁，性能进一步恶化

### `MISSING_BOUNDARY_CASE`（5 次）

- `M6-003` — **路线**：直接用比值判别法对 u_n(x) 求 lim|u_{n+1}/u_n|，得 x²，讨论 |x|<1 后就写收敛域 (-1,1)
  - 为什么差：漏掉端点 x=±1 的单独判定。本题 x=±1 时通项 ~ 2n 不趋零从而发散，所以收敛域确实是 (-1,1)，但这一步必须单独做——判别法在端点上给不出任何信息

  - 为什么差：原级数在 x=0（右端点）收敛、在 x=-4（左端点）发散；平移后右端点 5 收敛、左端点 1 发散，故应为 (1,5]。写成 (1,5) 丢了 x=5

  - 为什么差：两个端点的开闭都必须由题给条件具体判定：x=0 收敛靠莱布尼茨（用到'单调减少+趋零'），x=2 发散靠 S_n 无界。少用一条条件就会选错

### `UNRESOLVED_CONSTRAINT_CONFLICT`（3 次）

  - 为什么差：引脚数受封装尺寸、成本、信号完整性限制，加引脚会推高成本并恶化噪声；减少地址位数等于放弃容量，违反"容量要大"的原始需求。
- `C3-010` — **路线**：把页表放进更快的存储器（或把页表整体做成 SRAM）
  - 为什么差：页表规模与地址空间成正比（大地址空间下页表极大），全用 SRAM 实现页表在面积与成本上不可行；这条路的资源需求本身违反约束。

### `NEWTON_LEIBNIZ_BLIND_APPLICATION`（3 次）

- `M3-010` — **路线**：凑微分得原函数 F(x)=(1/√2)arctan(tan x/√2)，直接代入上下限算 F(3π/4)-F(0)
  - 为什么差：F 在 x=π/2 无定义，不是 [0,3π/4] 上的原函数；硬套得到 (1/√2)arctan(-1/√2)<0，与'被积函数恒正、积分必正'矛盾（讲义明确指出这显然是错误的结果）
- `M3-010` — **路线**：用万能公式令 t=tan x 换元，把整个区间 [0,3π/4] 一次换掉
  - 为什么差：t=tan x 在 x=π/2 处发散，换元函数在该点不连续，同样必须拆区间；一次换元会掩盖这个断点
- `M3-017` — **路线**：对 ∫_0^x f(t)dt/x 用洛必达法则，得 lim f(x)=lim(x-[x])，但该极限不存在
  - 为什么差：F(x)=∫_0^x f(t)dt 在整数点不可导（跳跃间断点处 F 左右导数不等），F'(x)=f(x) 不成立；即使形式算出 lim f(x)，该极限振荡不存在，洛必达路线直接卡死

### `PREMATURE_ABSOLUTE_VALUE`（3 次）

- `M3-018` — **路线**：把 |∫_0^1 f| 直接写成 ∫_0^1|f| 后用 M/2 的估计
  - 为什么差：M/2 不是目标；且'先取绝对值'在这一步会丢掉 f 在区间两端为零所蕴含的抵消效应（f 必须穿过零点，正负部分相互抵消）
- `M3-024` — **路线**：把 |∫_0^2 f| 直接写成 ∫_0^2|f| 后逐点估计 f
  - 为什么差：f(1)=0 且 f'' 有界意味着 f 在区间上有正负抵消；先取绝对值丢掉抵消效应，只能得到比 1/3 松的界
- `M6-016` — **路线**：由 a_n<b_n 且两个级数都收敛，认为 Σ|a_n| ≤ Σ|b_n|，从而'Σb_n 绝对收敛 ⇒ Σa_n 绝对收敛'，再判为必要不充分
  - 为什么差：a_n<b_n 只对实数序成立；当 a_n 为负、b_n 为正时 |a_n| 可以远大于 |b_n|。绝对值破坏序关系，这条不等式不成立

### `MISMATCHED_ENCODING_ORDER`（3 次）

- `M6-001` — **路线**：对 S(x) 求一次导数，试图让 n a_n 出现并与递推的 n 权重挂钩
  - 为什么差：递推的权重是 n(n-1)（二次），一阶导只产生 n（一次）；递推的 shift 是 2，一阶导的 shift 是 1——阶数与 shift 两处都不匹配，一阶导无法把 a_{n-2} 换进来
- `M6-003` — **路线**：对原级数整体逐项求导，试图让分母 2n+1 消失
  - 为什么差：通项是 x^{2n}，求导得 2n·x^{2n-1}，分母 2n+1 原封不动留在系数里；必须先提一个 x（或换元 t=x²）把分母与幂次的错位对齐，否则求导消不掉分母
- `M6-004` — **路线**：直接对 Σ(-1)^{n-1}x^{2n}/(2n-1) 逐项求导
  - 为什么差：求导得 Σ(-1)^{n-1}·(2n/(2n-1))·x^{2n-1}，分母 2n-1 没消掉反而多了个 2n；必须先提因子 x 把幂次与分母对齐，动作顺序不能颠倒

### `UNJUSTIFIED_SYMMETRY_TRANSFER`（1 次）

- `M3-004` — **路线**：看到 sin x/(1+x²) 是奇函数、区间 (-∞,+∞) 对称，直接写 ∫_{-∞}^{+∞}=0，判定 (D) 收敛
  - 为什么差：结论碰巧对，但推理不成立：若换成 x³ 就会得到 ∫_{-∞}^{+∞}x³=0 这种错误（讲义同节明确举了此反例）。缺少'单侧收敛'这一步，等于把 lim_{R}∫_{-R}^{R} 偷换成 ∫_{-∞}^{+∞}

### `DEPENDENCY_ORDERING`（1 次）

- `M5-015` — **路线**：只注意到 y1 + y2 = 2(1+x^2)^2 是一个解，就直接代入求 q
  - 为什么差：代入时仍需 p(x)，而 p 尚未确定；顺序颠倒会卡住。必须先由两解之差定 p，再回代定 q
