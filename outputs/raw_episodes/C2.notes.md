### 证据摘录的机械保证

本 worker **没有手打任何 `evidence_excerpt`**。流程是：

1. `_gen_c2_excerpts.py` 按 `(repo_path, 起行, 止行)` 从源文件 `split("\n")` 切出**连续行区间**；
2. 立即回比：把切出的文本在整个源文件里做子串查找，输出 `VERBATIM_FAIL`；

4. `_verify_c2.py` **重新从磁盘读 `C2.jsonl`**，再次对 `source.repo_path` 做子串校验。

三轮独立校验结果均为 **0 失败**。因此本文件不存在 SPEC §6.1 列举的三种违规（省略号拼接、插入箭头/标注、多处重组）。

## 五项显式记录（任务书 §「每条 Episode 必须显式记录这五项」）的落位

任务书要求"当前状态 / 允许动作 / 动作前置条件 / 动作后不变量 / 潜在全局后果"逐条记录。落位如下：

| 要求 | 承载字段 | 说明 |
|---|---|---|
| 当前状态 | `system_state` + `state_transition` 的起点 | 写成"状态 = (…)"的具体组合，不是"进程在运行"这类空话 |
| 允许动作 | `solution_skeleton` + `state_transition` 的迁移边 | 每个迁移边写明"事件 → 新状态" |
| 动作**前置条件** | `invariants` + `naive_routes` | 前置条件在 `invariants` 里作为必须成立的条件列出；违反它的那条路写进 `naive_routes` |
| 动作后**不变量** | `invariants` | 每条 Episode 都给出可校验的不变量（如 `empty+full=n`、`pits+empty=3`、`count>0 ⟺ rw 被读者持有`） |
| **潜在全局后果** | `local_vs_global_effect` | 每条都写成"局部动作 → 全局后果"的因果句，不是泛泛而谈 |

例（`C2-002`）：当前状态 `(empty, full, mutex 占用位)` → 允许动作 `P(empty)` → 前置条件"不得在持有 mutex 时等待 empty/full" → 不变量 `empty+full=n` → 全局后果"一次局部等待若在持锁状态下发生，会把缓冲区对所有进程关死，局部等待升级为全局死锁"。
