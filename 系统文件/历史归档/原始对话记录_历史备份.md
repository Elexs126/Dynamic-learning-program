> 你这里真正要解决的不是“选哪一个来源当唯一标准”，而是把不同来源分配到不同职责。协议本身已经暗示了这个方向：课程骨架、题目主知识点、方法、前置和错误类型不能混成一个标签字段。下面我按这个原则把几种来源拆开。
</details>

结论是：不要让这些来源直接“争夺一个最终标签”，也不要选其中一套完全统治其他来源。应该建立一个自己的规范标签体系，同时保留各来源的原始标签，把它们分成不同职责。

| 来源 | 应承担的职责 | 能否直接作为最终标签 |
|---|---|---|
| 官方考纲 | 确定知识范围和上层目录 | 通常太粗，不能单独承担终端标签 |
| 权威教材/练习书 | 提供教学章节、常用细分和候选标签 | 可以作为重要参考，但不是绝对真理 |
| 非官方统计网页 | 批量导入、初步统计、提供候选标签 | 不能直接用于最终统计 |
| 你的个人分类 | 形成适合你的学习视图、别名和能力关系 | 不宜直接替代考研标签 |
| AI判断 | 批量提出候选标签、发现冲突、辅助审查 | 不能自动视为正确标签 |
| 题目本身及评分步骤 | 判断这道题实际考查什么 | 这是决定主标签的核心证据 |

最关键的区分是：

> “这道题属于教材哪一章”，不等于“这道题的主知识点是什么”。

建议把每道题拆成几个不同字段，而不是只保存一个 `label`：

```text
official_path       官方考纲路径
textbook_section    教材章节
main_knowledge      最终主知识点
secondary_knowledge 次知识点
method              解法或技巧
prerequisite        前置能力
source_labels       各来源原始标签
label_source        最终标签依据
confidence           标签置信度
review_status        是否经过审查
```

例如，一道题可以同时拥有：

```text
official_path:       微积分 > 一元函数积分学
textbook_section:    某教材第X章
main_knowledge:      某个具体的积分能力
method:              换元、分部积分等
source_labels:       网站标签、教材标签、AI标签、个人标签
```

其中真正用于考频和目标分值统计的，只有 `main_knowledge`；教材章节和网站分类只是辅助视图。

主知识点的判断应该遵循协议第七部分的标准：

> 如果只能保留一个得分目标，这道小问主要是因为哪种能力获得分数？

因此，最终标签的判断顺序应当大致是：

1. 先看原子化后的具体小问。
2. 看题目要求和评分步骤。
3. 确定它对应的官方考纲范围。
4. 用权威教材提供合适的细粒度名称。
5. 用网页、个人分类和AI结果进行交叉参考。
6. 最终只确定一个主知识点，必要时补充次知识点。

这里的“交叉参考”不是简单投票。教材、网页和AI可能都复制了同一种传统分类，所以三个来源一致，也不代表有三份独立证据。

几种来源的具体定位可以这样理解：

- 官方考纲是“边界和地图”，防止我们创造出考纲之外的体系。
- 权威教材是“教学操作目录”，帮助我们把考纲粗粒度拆成可以学习和诊断的能力。
- 真题评分步骤是“最终裁判”，决定主知识点到底是什么。
- 网页分类是“已有的半成品数据”，适合批量导入，但必须经过映射和抽查。
- 你的分类是“个人学习视图”，非常有价值，但最好作为别名、理解方式或能力关系保存。
- AI是“标注助手”，可以提出标签和理由，但不能凭自己搜索到的常见分类自动定案。

你的个人分类不需要被废弃。更合理的做法是：建立一个稳定的考研主标签体系，再给每个标签允许一个或多个个人别名。这样既能保证考频统计与考纲、真题一致，也能让你用自己最容易理解的方式学习。

对于暂时无法判断的题目，可以先保留一个较粗的主标签，并标记低置信度或待审查，而不是强行制造一个看似精确的标签。协议中的“全库粗标、调用时精标”就是为了解决这个问题：先让所有题目可用，再对启动锚点、近期候选题、诊断题和审计题做精细审查。

还有一个边界：数学一和408应当各自维护标签体系和统计，不能因为某些抽象能力相似就把两科的知识点直接混算。

核心原则如下：

| 要回答的问题 | 最高权重来源 |
|---|---|
| 是否属于考试范围 | 官方考纲 |
| 教学上放在哪一章 | 权威教材 |
| 这道题主要考什么 | 题干要求、评分目标、合法解法的共同稳定部分 |
| 哪些步骤得分 | 评分标准和评分步骤 |
| 批量产生候选 | 统计网页、AI |
| 适合你如何理解 | 你的个人分类 |

因此，最终标签不是某一个来源直接提供的，而是项目自己建立的“规范标签”，来源只是提供不同证据：

```text
官方考纲：确定边界
权威教材：提供合理颗粒度和教学目录
题目与评分：决定具体题目的主考查点
网页：批量预标注
AI：候选生成和冲突发现
个人分类：个人学习视图
```

最需要避免的是把以下几种东西混成一个标签：

```text
考纲范围：一元函数极限
教材章节：泰勒公式
主考查点：判断局部展开后的主导阶
方法：泰勒展开、洛必达法则
前置：导数、代数变形
个人视图：二阶展开套路
```

例如一道极限题的标准解析用了洛必达法则，但题目允许用泰勒展开。那么“洛必达法则”应该是方法标签，不能因为解析采用了它就把题目主标签定成“洛必达法则”。主标签应尽量满足：

> 换一种合法解法后，这个标签仍然能够解释题目要求获得的分数。

另一个重要发现是：

> “可独立判分的小问”不一定等于“只考一个能力”。

它解决的是评分原子化问题，不一定解决能力纯度问题。一个小问可能包含“判断定理适用条件”和“完成后续计算”两个不同能力。因此可以保留：

```text
question_atom       可独立判分的小问
main_knowledge      主知识点，服务目标考频
secondary_knowledge 次知识点或共同考查点
method              解法
prerequisite        前置能力
score_contribution  明确评分步骤的分值归属
```

我建议不推翻协议的“一主标签”规定，而是补充一句隐含原则：

> 主知识点用于目标考试的主统计和任务索引；它不承担完整的教学结构和个人能力诊断。

1. 以官方考纲作为上层边界。
2. 以权威教材提供终端知识点的候选颗粒度。
3. 以题干和评分要求决定该题的主知识点。
4. 以网页和 AI 进行批量预标注，不自动定案。
5. 保留所有原始来源和映射关系。
6. 将个人分类作为个人视图，不混入公共考频。

真正试标时，不是只生成一道题就结束，而是从数学一真题中抽取一小批，例如：

3. 评分单元分值是否能加回原题总分。
4. 哪些内容应该是方法，哪些才是主知识点。
5. 标签是否能直接导向后续教学或训练。

> ## 1. Agent 拆分原则
>
> 采用**按标签类别纵向拆分**，不要按题号横向拆分。
>
> 也就是说：
>
> - 每个子 Agent 负责一组彼此相关、可以独立判断的标签；
> - 每个子 Agent 都应处理本批次的**全部题目**；
> - 不要把题目拆成“1–10题给一个 Agent、11–20题给另一个 Agent”这种形式；
> - 这样做的目标是让同一类标签始终由同一个 Agent 按统一尺度判断，减少跨 Agent 的标注漂移。
>
> 具体哪些标签组合在一起，由主 Agent 根据标签之间的语义关联和共享判断过程自行合理分组，不需要机械地平均分配字段。
>
> ## 2. 并行数量限制
>
> 整个标注阶段：
>
> - **最多并行启动 5 个标注 Agent；**
> - 这 5 个 Agent 由主 Agent 直接创建；
> - **禁止任何子 Agent 再创建、派生或调用新的子 Agent；**
> - 禁止按题号、章节、批次等再次递归拆分任务；
> - Agent 层级深度固定为 1。
>
> 即：
>
> 主 Agent\
> → 最多 5 个并行标注 Agent\
> → 到此为止，不得继续 fan-out。
>
> 即使单个 Agent 需要处理很多题，也应由该 Agent 自己连续完成，不得为了加速再次拆出多个 worker。
>
> ## 3. 标签分组要求
>
> 5 个 Agent 之间的标签职责应：
>
> - 尽量互不重叠；
> - 尽量减少重复判断；
> - 将语义紧密、判断过程高度共享的标签放在同一个 Agent；
> - 优先保证同一类标签在全部题目上的一致性，而不是追求最大并发数量。
>
> 对于题库已经确定的原始事实字段，例如题号、年份、原始分值、考试类别等，应视为锁定输入，不要让多个分析 Agent 重复推断或重新创造。
>
> ## 4. 最终 QA
>
> 5 个标注 Agent 全部完成以后，再启动 **1 个独立 QA Agent**。
>
> QA Agent 只负责最终质量检查，包括：
>
> - 字段是否缺失；
> - 同类标签在不同题目之间的尺度是否一致；
> - 不同标签之间是否存在逻辑冲突；
> - 是否违反标签定义、枚举范围、多标签数量上限等规则；
> - 是否把题源事实和 AI 推断混淆；
> - 是否存在明显误标或异常值。
>
> QA Agent 可以指出并修正明确错误，但不要重新把整个任务拆成新的子任务，也不得继续派生 Agent。
>
> 因此完整结构应保持为：
>
> **5 个并行标注 Agent → 汇总 → 1 个最终 QA Agent**
>
> 而不是形成多层递归 Agent 树。
>

## 先固定四条总规则

### 1. 这里的 L0—L3 是标注深度

不是提示等级。

- **标注深度 L0—L3**：决定给题目建立多少标签。
- **提示等级 L0—L4**：决定给学生多少解题帮助。

以后必须写“标注深度 L3”或“提示等级 L3”，不能只写一个裸的“L3”。

### 2. 标注是逐层累积的

L3 题目必须已经包含 L0、L1、L2 的结果，L3 只是继续增加更细的信息。

```text
L0 原始事实
  + L1 候选标签
  + L2 审核后的标签
  + L3 评分、证据、关系
```

### 3. 标签和标签依据不是一回事

例如：

```text
main_knowledge
= 题目最终属于哪个知识点

label_provenance
= 这个知识点标签是依据什么判断出来的
```

不能把二者都简称为“来源”。

### 4. 不确定时必须保留不确定

允许使用：

```text
candidate
verified
needs_review
not_applicable
```

不能为了让表格看起来完整，就强行制造确定标签。

# 一、标注深度 L1

L1 的作用是：**对全库题目进行快速、统一、低成本的候选标注。**

L1 覆盖全部题目，包括暂时不会精细处理的题目。

## L1-1：粗粒度考纲路径

字段建议叫：

```text
official_scope_coarse
```

### 它标什么

标注题目在官方考纲或课程骨架中的大致位置。

例如：

```text
高等数学 > 函数、极限与连续
```

或者：

```text
线性代数 > 矩阵
```

### 它不标什么

它不是：

- 题目的来源；
- 具体解题方法；
- 最细的知识点；
- 学生能力；
- 难度。

例如：

```text
高等数学 > 函数、极限与连续
```

是考纲路径。

```text
等价无穷小参数判定
```

是具体知识点。

```text
泰勒展开
```

是方法。

三者不能混在一起。

### L1 的粒度

L1 只要求粗粒度路径，不要求精确到最细操作。

如果示例里出现：

```text
coarse
precise
```

只能理解为：

- `coarse`：L1 的粗粒度路径；
- `precise`：后续可补充的细化路径。

不能因此认为 L1 一开始就必须完成最细知识点标注。

---

## L1-2：标签依据来源

字段建议叫：

```text
label_provenance
```

也可以叫：

```text
tag_basis
```

### 它标什么

它说明：**当前这个候选标签，是依据什么材料判断出来的。**

例如：

```text
[
  "official_syllabus",
  "primary_textbook",
  "question_semantics"
]
```

也可以是：

```text
[
  "unofficial_index",
  "ai_inference"
]
```

### 它不标什么

它不是题目本身来自哪里。

题目本身的来源应该由 L0 记录：

```text
question_source
= 数学一 2009 年真题
```

L1 的标签依据则是：

```text
label_provenance
= 官方考纲 + 主教材章节 + 题目语义判断
```

二者的区别是：

| 字段 | 回答的问题 |
|---|---|
| `question_source` | 这道题从哪里来？ |
| `label_provenance` | 这个标签根据什么判断？ |
| `source_reliability` | 这个来源可靠吗？ |
| `data_role` | 这道题在系统中怎么使用？ |

以后禁止把这四个东西都叫“来源”。

---

## L1-3：候选主能力

字段建议叫：

```text
candidate_main_ability
```

### 它标什么

它是对题目主要考查能力的**初步猜测**。

它回答：

> 如果现在只能猜一个，这道题大概是在考什么能力？

例如：

```text
高阶极限中的首个非零项判断
```

### 它不是最终主能力

L1 的候选主能力允许错误，也允许后续修改。

```text
L1 candidate_main_ability
= 初步判断

L2 audited_main_ability
= 审核后确定的最终主能力
```

因此，L1 的候选主能力不能直接用于最终考频统计。

### 它不应该写成什么

不能把方法写成主能力：

```text
错误：泰勒展开
```

因为泰勒展开是方法。

更合适的是：

```text
正确：高阶极限中的首个非零项判断
```

也不能把前置能力写成主能力：

```text
错误：基本极限运算
```

如果基本极限运算只是做题前需要具备的东西，它应当进入 L2 的前置能力。

---

## L1-4：置信度

字段建议叫：

```text
confidence_by_field
```

### 它标什么

置信度必须针对具体判断，而不是只给整道题一个模糊的总分。

例如：

```text
{
  "scope": "high",
  "candidate_main_ability": "medium",
  "duplicate_candidate": "low"
}
```

### 建议标准

```text
high
= 题干完整，考纲归属明显，几乎没有合理竞争解释

medium
= 基本判断明确，但存在一个合理的替代解释

low
= OCR、图示、题干或来源存在问题，无法稳定判断
```

### 它不代表什么

置信度不是：

- 题目难度；
- 学生掌握程度；
- 来源权威程度；
- 标签的重要性。

这些都必须分别记录。

---

## L1-5：重复候选

字段建议叫：

```text
duplicate_candidate
```

### 它标什么

它标记：**这道题可能和另一条题目记录是同一道题或高度近似的复制题。**

例如：

```text
{
  "is_candidate": true,
  "possible_duplicate_ids": ["ZY30-GS-01-X03"],
  "basis": "题干、数据和问法高度一致",
  "status": "candidate"
}
```

### 它不标什么

以下情况不能判为重复题：

- 两道题属于同一章；
- 两道题考同一个知识点；
- 两道题都使用泰勒展开；
- 两道题解题结构相似。

这些可能是 L3 的同构关系，不是 L1 的重复候选。

### 重复和同构的区别

```text
重复
= 题目本身基本相同

同构
= 题目表面不同，但解题结构相同
```

---

# 二、标注深度 L2

L2 的作用是：**把 L1 的候选结果审核成可以用于教学和统计的正式标签。**

L2 不一定覆盖全部题目。核心题全量处理，其他题目可以分层处理。

## L2-1：审核后的主能力 / 主知识点

字段建议拆成：

```text
main_knowledge
audited_main_ability
```

### `main_knowledge` 标什么

它是最终规范化的主知识点标签。

例如：

```text
{
  "id": "M1-01-等价无穷小",
  "name": "等价无穷小的阶与参数判定"
}
```

每个原子必须有且只有一个主知识点。

它用于：

- 主考频统计；
- 主分值统计；
- Teacher 选择能力包；
- 判断题目主要给什么能力分。

### `audited_main_ability` 标什么

它是审核后的能力表达，回答：

> 学生最终需要能够完成什么任务？

例如：

```text
从局部渐近行为中提取主导项，并判断参数使两个无穷小等价。
```

### `main_knowledge` 和 `assessed_construct` 的区别

```text
main_knowledge
= 这道题属于哪个知识点

assessed_construct
= 学生需要表现出什么能力行为
```

例如：

```text
main_knowledge:
高阶极限中的首个非零项判断

assessed_construct:
判断需要展开到的阶数，并提取首个非零项
```

前者是分类标签，后者是能力描述。

`assessed_construct` 不是第二个知识点，也不能拿来重复统计考频。

---

## L2-2：次知识点

字段建议叫：

```text
secondary_knowledge
```

### 它标什么

只有当另一个知识点确实参与关键推理、明确得分步骤或题目明确要求迁移时，才标为次知识点。

### 数量限制

```text
选择题、填空题：
1 个主知识点 + 最多 1 个次知识点

解答题：
1 个主知识点 + 最多 2 个次知识点
```

### 它不标什么

以下内容不应该成为次知识点：

- 偶然使用的计算技巧；
- 普通代数化简；
- 任何出现过的公式；
- 只是在解题过程中顺手使用的工具。

这些应进入方法或前置能力。

### 它不等于共学任务簇

```text
secondary_knowledge
= 这一道题中实际参与的次要知识点

co_learning_cluster
= 多个能力在课程中需要共同建设的能力关系
```

两者不能互换。

---

## L2-3：主要方法

字段建议叫：

```text
primary_method
```

### 它标什么

它标注解决这道题最主要、最稳定的方法骨架。

例如：

```text
泰勒展开并保留首个非零项
```

或者：

```text
利用拉格朗日中值定理构造中间点
```

### 它不是主知识点

```text
主知识点：高阶极限中的首个非零项判断
主要方法：泰勒展开
```

方法回答“怎么做”，知识点回答“主要考什么”。

### L2 只写方法骨架

L2 不需要写完整解答过程，也不应该写最终答案。

例如可以写：

```text
建立特征方程，按根的类型写齐次解结构
```

不应该写成一整段推导。

### 替代方法放在哪里

主要方法放 L2。

其他合理方法放 L3 的：

```text
alternative_methods
```

---

## L2-4：必要前置

字段建议叫：

```text
prerequisites
```

必须区分：

```text
hard_prerequisite
= 缺少它就无法继续完成关键任务

soft_prerequisite
= 有它会更容易，但缺少它不一定阻止完成
```

例如：

```text
硬前置：极限基本运算
软前置：泰勒展开的熟练变形
```

### 前置能力不等于次知识点

如果一个知识点只是被调用，但不是本题主要考查对象，它优先考虑放前置或方法，而不是强行放进次知识点。

### 前置能力不应该无限添加

不能把完成题目过程中用到的所有基础知识都列成前置。

只保留会真正影响能否进入本题的关键能力。

---

## L2-5：难度档

字段建议叫：

```text
difficulty_band
```

它表示题目本身的认知和解题要求，不表示学生做这道题时的个人感受。

建议使用四档：

```text
basic
= 直接调用单一知识点，步骤短，几乎没有隐藏识别

intermediate
= 一个主知识点加标准前置，需要若干连续步骤

advanced
= 存在隐藏辨型、明显迁移、边界处理或多个关键步骤

very_advanced
= 多个知识点深度综合，方法不明显，证明/建模/推理负荷高
```

### 难度不能根据这些东西直接决定

不能因为：

- 分值高；
- 题型是解答题；
- 年份很早；
- 来源教材写了“难题”；
- 学生第一次做错；

就直接判断难度。

---

## L2-6：练习角色 / 数据使用角色

字段建议叫：

```text
data_role
```

它表示题目在系统中如何被使用，不表示题目从哪里来。

允许的角色包括：

```text
RAW
= 原始不可变档案

TARGET_PRIOR
= 用于目标考试频率和分值统计

STARTUP_TRAINING_ONLY
= 启动阶段训练题，不用于个人基线认证

TRAIN
= 普通训练题

ADAPTIVE_DIAGNOSTIC
= 自适应诊断题

FIXED_AUDIT
= 固定审计题组

SEALED
= 密封整卷题

AUX_OFFPOLICY
= 辅助题源，不计入目标考试主统计
```

例如：

```text
数学一真题
= question_source

TRAIN
= data_role
```

数学二真题、教材题、AI 生成题可以是题目来源，但如果不纳入数学一目标统计，则其 `data_role` 应体现辅助性质。

同一道原始题可以在不同视图中承担不同用途，但不能把题目来源改成练习角色。

---

# 三、标注深度 L3

L3 的作用是：**只对真题、诊断题、审计题和实际即将调用的题目，记录可执行的精细信息。**

L3 不是给所有 8125 道题都立即完整填写。

## L3-1：评分单元

字段建议叫：

```text
score_units
```

### 它标什么

评分单元是：

> 能够独立判分的最小题目单位。

规则是：

- 选择题天然是一个评分单元；
- 填空题天然是一个评分单元；
- 解答题只有明确的 `(1)(2)` 或独立得分步骤时才拆；
- 如果多个知识点不可分割地服务同一个得分目标，则保留为一个综合单元。

### 不能怎么做

不能为了让 JSON 看起来精细，就把一道 4 分题强行拆成：

```text
U1 1分
U2 1分
U3 2分
```

除非原始评分标准明确支持这个拆分。

---

## L3-2：分值归属

字段建议叫：

```text
score_attribution
```

### 它标什么

它说明每个评分单元的分值最终归属于：

- 主知识点；
- 次知识点；
- 方法操作；
- 综合目标；
- 尚不能确定。

### 重要规则

主知识点统计和分值归属不是一回事。

例如一道题总分 4 分：

```text
主知识点统计：整道题只算一次

评分归属：
U1：2 分，主知识点
U2：1 分，操作步骤
U3：1 分，最终综合结论
```

操作步骤不应被伪装成知识点。

如果没有明确评分依据：

```text
points_status = unresolved
```

不能凭感觉分成：

```text
60% / 30% / 10%
```

---

## L3-3：证据步骤

字段建议叫：

```text
evidence_steps
```

### 它标什么

它标的是：

> 阅卷时可以观察到、并据此判断该评分单元是否完成的关键证据。

例如：

```text
建立正确的特征方程
```

```text
正确处理积分区域和曲面方向
```

```text
明确写出满足题设的参数条件
```

### 它不等于参考答案

证据步骤不是：

- 完整解题过程；
- 最终答案；
- 参考解析；
- 逐行推导；
- 给学生看的提示。

它只记录“什么表现可以证明该得分单元完成”。

---

## L3-4：替代方法

字段建议叫：

```text
alternative_methods
```

### 它标什么

它标记其他同样合理、且在题设条件下可行的解法。

例如：

```text
primary_method:
泰勒展开

alternative_methods:
[
  "洛必达法则",
  "等价无穷小比较"
]
```

### 它不标什么

不能把所有可能沾边的公式都列进去。

只有真正能独立完成该题、并且适用条件成立的方法，才算替代方法。

也不能在这里写完整解答，只写：

- 方法名称；
- 适用条件；
- 与主方法的关系。

---

## L3-5：题间依赖

字段建议叫：

```text
inter_question_dependency
```

### 它标什么

它标注具体题目之间是否存在直接依赖。

例如：

```text
题 B 明确要求使用题 A 得出的中间对象
```

或者：

```text
同一大题的第 (2) 问必须建立在第 (1) 问结果之上
```

### 它不标什么

以下情况不能标为题间依赖：

- 两道题同属一章；
- 两道题使用同一个知识点；
- 两道题难度相近；
- 做题顺序上建议先做 A 再做 B；
- A 是 B 的能力前置，但题目本身没有直接关系。

能力前置属于 L2。

题间直接依赖才属于 L3。

如果没有明确依赖，应填写：

```text
none
```

不能根据题号顺序猜测依赖。

## L3-6：同构关系

字段建议叫：

```text
isomorphic_relation
```

### 它标什么

它标记不同题目是否具有相同的解题结构。

例如：

- 表面函数不同，但都要求提取首个非零项；
- 数字和背景不同，但都使用同一种分类计数模型；
- 题型不同，但核心推理链完全同构。

应该记录：

```text
cluster_id
structural_invariant
transfer_axis
```

例如：

```text
cluster_id:
LIMIT-HIGHER-ORDER-01

structural_invariant:
识别主导阶并提取首个非零项

transfer_axis:
函数形式变化、参数变化、题型变化
```

### 它不等于重复题

```text
duplicate_candidate
= 题目可能是同一道题

isomorphic_relation
= 题目不同，但解题骨架相同
```

也不等于：

```text
secondary_knowledge
```

更不等于：

```text
co_learning_cluster
```

## L3-7：综合组合

协议正文还出现过“综合组合”这个词。它不是新的知识点标签。

它表示：

> 一道题中多个主、次知识点、方法和前置能力如何共同组成一个任务。

它可以由以下字段组合得到：

```text
main_knowledge
secondary_knowledge
primary_method
prerequisites
score_units
isomorphic_relation
```

除非最终数据结构明确要求新增字段，否则不要再凭空增加一个含义不清的“综合能力”字段。

# 四、审核状态不是标注内容

`review_status` 是所有层级都可以附带的控制字段，不属于某一个具体知识点。

```text
candidate
= 机器或 Agent 初步提出，尚未充分审核

verified
= 已依据题干、考纲、教材或评分依据核对

needs_review
= 存在 OCR、图示、来源冲突或多个合理解释

not_applicable
= 这个字段对该题不适用
```

```text
DEMO_ONLY
```

只能表示“这是示范数据”，不能拿来代替正式审核状态。

审核状态最好按字段记录，例如：

```text
official_scope_status
main_knowledge_status
score_mapping_status
```

不要只给整道题一个总状态，让人不知道到底哪个字段有问题。

## 1. `audited_main_ability` 和 `assessed_construct`

他的疑问成立。之前我同时使用了：

```text
candidate_main_ability
audited_main_ability
main_knowledge
assessed_construct
```

这确实容易让人误以为有四个不同字段。

最终应当这样定：

```text
L1 candidate_main_ability
= 初步猜测这道题主要考什么

L2 main_knowledge
= 审核后的唯一规范主知识点

L2 assessed_construct
= 学生需要表现出的具体能力行为
```

例如：

```text
L1 candidate_main_ability:
高阶极限中的首个非零项判断

L2 main_knowledge:
等价无穷小的阶与参数判定

L2 assessed_construct:
识别主导阶，并判断参数使两个无穷小等价
```

因此：

- `candidate_main_ability` 和 `main_knowledge` 是同一判断在不同审核阶段的版本；
- `assessed_construct` 不是主知识点，而是对学生行为的描述；
- `audited_main_ability` 不再作为独立字段保存，它只是 `main_knowledge` 的说明性别名；
- 不能同时保存 `audited_main_ability` 和 `main_knowledge`，否则重复。

## 2. `source_reliability`

他的疑问也成立。前一版把“题目来源可靠度”和“标签判断置信度”混在了一起。

最终拆成三层：

```text
L0 question_source
= 题目本身从哪里来

L0 source_reliability
= 这个题目来源本身是否可靠

L1 label_provenance
= 标签判断依据了什么

L1/L2/L3 confidence
= 对具体标签判断有多确定
```

例如：

```text
question_source:
数学一 2009 年官方真题

source_reliability:
high

label_provenance:
官方考纲 + 主教材 + 题目语义

confidence:
main_knowledge = high
score_attribution = medium
```

所以最终规则是：

- `source_reliability` 是**原始题目来源的元数据**，归 L0；
- 它不是 L2/L3 的标签字段；
- 标签判断的可靠程度使用 `confidence`；
- `source_reliability` 可以针对一个来源记录，不需要对每个标签重复填一遍；
- `confidence` 应针对具体字段记录，不能只给整道题一个总置信度。

## 3. L3 的“真题”是否包括数学二、数学三



但还要再精确一步：

**数学一和 408 的全部真题，也不是一开始全部做完整 L3。**

协议的“调用时精标”规定：

```text
L0/L1：
全库粗标

L2：
核心题全量，其他题分层处理

L3：
只处理实际需要的题
```

实际需要包括：

- STARTUP 锚点；
- 当前训练题；
- 诊断题；
- 固定审计题；
- 即将调用的题；
- 需要进行评分和同构分析的题。

所以 L3 的“真题”应解释为：

> 目标真题中已经进入精标池或实际调用流程的题目，而不是所有数学一、408、数学二、数学三真题全部一次性做 L3。

## 4. `data_role` 是静态标签还是运行状态

他的判断是对的：`data_role` 不应该和主知识点、难度档放在同一种永久静态标签里。

应该区分：

```text
静态题目标注：
main_knowledge
secondary_knowledge
assessed_construct
primary_method
prerequisites
difficulty_band
```

和：

```text
动态使用角色：
RAW
TARGET_PRIOR
STARTUP_TRAINING_ONLY
TRAIN
ADAPTIVE_DIAGNOSTIC
FIXED_AUDIT
SEALED
AUX_OFFPOLICY
```

动态使用角色会随着系统运行变化，不能直接覆盖原值。

例如一条题目记录可能有这样的使用历史：

```text
question_id: M1-09-C-T01

usage_history:
- RAW
- TARGET_PRIOR
- STARTUP_TRAINING_ONLY
- TRAIN
```

因此正式数据结构最好拆成：

```text
question_tags
= 静态或版本化的知识标签

question_usage_roles
= 题目在不同时间、不同视图中的使用角色
```

如果暂时只能放在一个 JSON 中，也应该写成：

```text
data_roles:
[
  {
    "role": "TRAIN",
    "valid_from": "...",
    "valid_to": null
  }
]
```

而不是每次改变角色时直接覆盖旧值。

# 题库标注深度 L0—L3 正式执行定义

四层标注逐层累积：

```text
L0 原始事实
  ↓
L1 候选粗标
  ↓
L2 审核后的正式知识与教学标签
  ↓
L3 评分、证据和题目关系
```

完成 L3 的题目必须同时保留 L0、L1、L2、L3，不能只保存 L3。

## L0：原始事实层

L0 只回答：

> 这到底是哪一道题，它从哪里来，原始文件是什么状态？

L0 尽量由脚本直接提取，不依赖 AI 推理。

### `question_id`

全局唯一题目 ID。

例如：

```text
M1-08-C-T08
M1-08-F-T09
M1-08-A-T15
408-09-C-T01
WD-DS-C-2.2-T03
ZY30-GS-01-L1.01
```

数学一、数学二、数学三的 ID 必须包含题型代码 `C/F/A`，不能写成含义不完整的 `M1-08-T08`。

### `exam_track`

题目属于哪条考试轨道：

```text
MATH1
MATH2
MATH3
CS408
```

### `subject_area`

题目属于哪一个学科分区：

```text
calculus
linear_algebra
probability
data_structure
computer_organization
operating_system
computer_network
```

`exam_track` 和 `subject_area` 不是一回事。

例如：

```text
exam_track: MATH1
subject_area: calculus
```

### `question_source`

题目本身来自哪里。

例如：

```text
数学一 2009 年官方真题
408 2021 年官方真题
张宇基础30讲
张宇1000题
王道408
408经典练习题
```

这个字段只说明题目来源，不说明标签怎么判断。

### `source_reliability`

评价原始题目来源本身的可靠程度。

例如：

```text
high
medium
low
unknown
```

含义：

```text
high
= 官方试卷、权威出版物或可以直接核对的原始资料

medium
= 较可靠的教材、整理资料或有明确出处的网页

low
= 来源不明、二次转载、OCR 严重损坏或无法核对

unknown
= 暂时没有足够信息判断
```

它不表示 AI 标签是否正确。标签正确程度用 `confidence` 表示。

### `year`

真题年份。

教辅题没有真实考试年份时填写：

```text
not_applicable
```

不能凭空制造年份。

### `question_number`

原始题号，例如：

```text
T08
第41题
例1.1
习题03
```

### `question_type`

统一后的题型，只使用：

```text
choice
fill
analytical
```

“证明题”“计算题”“综合题”不是同一级题型，而是任务形式或结构描述。必要时另设：

```text
task_form
```

不能把“泰勒展开”“矩阵秩”写进 `question_type`。

### `original_section`

题目在原始题源中的章节或专题。

例如：

```text
张宇30讲 > 高等数学 > 第1讲
王道408 > 数据结构 > 2.2 顺序表
```

它表示原书怎么组织题目。

### `question_completeness`

题干文件完整性：

```text
complete
incomplete
needs_review
```

检查：

- 文字是否完整；
- 公式是否损坏；
- 图片是否缺失；
- 选项是否完整；
- 子问题是否缺失。

### 解析完整性

解析是否完整可以作为独立的文件摄取质量检查，但不属于 L0—L3 的知识标签。

最终 L3 文件不能保存：

```text
answer
solution
reference_answer
reference_solution
完整解析
```

原始答案和解题步骤可以被读取作为判断证据，但不能写入最终标签结果。

## L1：候选粗标层

L1 覆盖全部题目。

L1 只回答：

> 快速看这道题时，它大概属于哪里、大概考什么、是否可能和其他记录重复？

L1 的结果都是候选结果，不是最终结论。

### `official_scope_coarse`

按统一考纲或课程骨架给出的粗粒度路径。

例如：

```text
高等数学 > 函数、极限与连续
408 > 数据结构 > 线性表
```

它不是：

- 原始题源章节；
- 最细知识点；
- 解题方法；
- 难度。

`original_section` 回答“原书放在哪里”。

`official_scope_coarse` 回答“按统一考纲应该放在哪里”。

如果后续需要更细的路径，可以在同一个 `official_scope` 对象中增加：

```text
official_scope.precise
```

但 `precise` 不是 L1 的强制要求，不能因为少填了它就判定 L1 不完整。

### `label_provenance`

说明候选标签依据什么产生。

例如：

```text
official_syllabus
primary_textbook
question_semantics
unofficial_index
ai_inference
human_review
```

它回答：

> 我们为什么把这道题暂时归到这里？

它和 `question_source` 完全不同：

```text
question_source
= 题目本身从哪里来

label_provenance
= 标签判断依据什么
```

### `candidate_main_knowledge`

这是原来“候选主能力”的机器字段。

之所以改名，是因为它最终对应的是 `main_knowledge`，而不是 `assessed_construct`。

它回答：

> 如果现在只能先猜一个，这道题大概主要属于哪个知识点？

例如：

```text
高阶极限中的首个非零项判断
```

它只是候选判断，不能直接用于最终考频统计。

关系是：

```text
L1 candidate_main_knowledge
        ↓ 审核
L2 main_knowledge
```

### `confidence_by_field`

置信度必须针对具体字段。

例如：

```json
{
  "official_scope_coarse": "high",
  "candidate_main_knowledge": "medium",
  "duplicate_candidate": "low"
}
```

标准：

```text
high
= 基本不存在合理竞争解释

medium
= 基本判断明确，但存在一种合理替代解释

low
= OCR、图示、题干或来源存在明显不确定
```

它不表示题目难度，也不表示来源可靠度。

### `duplicate_candidate`

表示这道题是否可能和另一条记录是同一道题或轻微改写版本。

例如：

```json
{
  "is_candidate": true,
  "possible_duplicate_ids": ["ZY30-GS-01-X03"],
  "basis": "题干、数据和问法高度一致",
  "status": "candidate"
}
```

重复题和同构题必须区分：

```text
duplicate
= 两条记录可能其实是同一道题

isomorphic
= 两道不同题，但核心解题结构相同
```

同一章、同一知识点、同一种方法，不足以判定重复。

## L2：审核后的正式知识与教学标签

L2 的范围是：

- 核心题库全量；
- 其他来源按照优先级分层处理。

按当前项目优先级，核心 L2 全量为：

```text
数学一真题：431
张宇基础30讲：876
408真题：846
合计：2153
```

其中：

```text
数学一真题 + 408真题 = 1277
```

用于目标考试考频、分值和期望分统计。

张宇基础 30 讲虽然属于核心训练来源，但不能并入数学一目标考试统计。

数学二、数学三、张宇1000题、王道408、408经典练习题等，不做第一批全库精细 L2；它们按层级或实际需要调用。

### `main_knowledge`

这是审核后的唯一主知识点。

它回答：

> 如果只能保留一个得分目标，这道题主要是为什么知识点给分？

例如：

```json
{
  "id": "M1_LIMIT_HIGH_ORDER_LOCAL_BEHAVIOR",
  "name": "高阶极限中的首个非零项判断"
}
```

每个题目原子必须有且只有一个主知识点。

主知识点可以用于：

- 目标考频统计；
- 主分值统计；
- Teacher 能力包；
- 学习前沿；
- 主错误诊断。

### `assessed_construct`

这是学生必须表现出的具体能力行为。

例如：

```text
判断需要展开到哪一阶，并提取首个非零项。
```

或者：

```text
识别主导阶，并判断参数使两个无穷小等价。
```

二者的区别必须固定：

```text
main_knowledge
= 题目属于哪个知识点

assessed_construct
= 学生要做出什么行为，才能证明自己会这个知识点
```

`assessed_construct` 不是第二个知识点，也不参与独立考频统计。

### `secondary_knowledge`

除主知识点之外，只有在以下情况下才记录次知识点：

- 它参与关键推理；
- 它对应明确评分步骤；
- 题目明确要求跨知识点迁移。

数量限制：

```text
选择题、填空题：最多 1 个次知识点

解答题：最多 2 个次知识点
```

不能因为题目过程中顺手用了某个公式，就把它列为次知识点。

次知识点不等于：

```text
前置能力
主要方法
共学任务簇
同构关系
```

### `primary_method`

主要解法骨架。

例如：

```text
局部展开并比较首个非零项
建立特征方程并按根的情况构造解
利用高斯公式将通量转化为体积分
```

它回答“主要怎么做”，不回答“主要考什么”。

L2 只记录方法骨架，不保存完整答案或完整解题过程。

### `prerequisites`

题目主任务开始前需要的关键能力。

分为：

```text
hard_prerequisite
= 缺少它就基本无法完成主任务

soft_prerequisite
= 有它会更容易，但没有它不一定无法完成
```

不能把所有用过的基础公式都列成前置能力。

### `difficulty_band`

题目自身的静态难度，不是学生当天的个人感受。

暂定四档：

```text
basic
intermediate
advanced
very_advanced
```

判断标准：

```text
basic
= 单一知识点直接调用，步骤短，几乎无隐藏辨型

intermediate
= 一个主知识点，调用标准前置，需要连续多步

advanced
= 存在隐藏辨型、明显迁移、边界处理或多个关键步骤

very_advanced
= 多知识点深度综合，方法不明显，证明或建模负荷很高
```

不能因为题目分值高、学生第一次做错，就自动判为高难。

## 使用角色不属于永久知识标签

`data_role` 或 `practice_role` 表示：

> 系统当前拿这道题做什么？

它不是题目永久的知识属性。

使用角色包括：

```text
RAW
TARGET_PRIOR
STARTUP_TRAINING_ONLY
TRAIN
ADAPTIVE_DIAGNOSTIC
FIXED_AUDIT
SEALED
AUX_OFFPOLICY
```

正式存储应当与 `question_tags` 分离：

```text
question_tags
= main_knowledge
  assessed_construct
  secondary_knowledge
  primary_method
  prerequisites
  difficulty_band

question_usage_roles
= 题目在不同时间、不同视图中的使用角色
```

如果角色发生变化，不能覆盖旧记录，而应保留历史：

```json
[
  {"role": "RAW"},
  {"role": "TARGET_PRIOR"},
  {"role": "TRAIN"}
]
```

## L3：评分、证据和题目关系

L3 只对实际进入精标池的题目执行，包括：

- STARTUP 锚点；
- 当前训练题；
- 诊断题；
- 固定审计题；
- 实际即将调用的题；
- 需要评分或同构分析的题。

这里的“真题”主要指目标考试真题：

```text
数学一
408
```

数学二和数学三属于辅助来源，不做全库 L3；只有实际调用时才做。

数学一和 408 也不是一开始全部做 L3。它们先完成 L0/L1，L2按核心范围处理，L3按实际调用处理。

### `score_units`

能够独立判分的最小题目单位。

规则：

```text
选择题通常是一个评分单元
填空题通常是一个评分单元
解答题只有明确独立小问或可靠独立评分依据时才拆
```

不能为了追求精细，凭感觉把 4 分题拆成：

```text
1分 + 1分 + 2分
```

如果没有可靠的子分值证据，就保持整体单元，并标记分值细分未确定。

### `score_attribution`

说明评分单元的分值归属于什么：

```text
主知识点
次知识点
方法操作
综合目标
无法确定
```

主知识点考频统计和评分归属不是同一件事。

一道 4 分题仍然只有一个主知识点；内部可以记录多个操作型评分证据，但不能因此创造多个主知识点。

### `evidence_steps`

记录阅卷时可以观察到的关键得分证据。

例如：

```text
正确建立特征方程
正确识别主导阶
正确处理积分方向
正确写出参数条件
```

它不是：

- 参考答案；
- 完整解题过程；
- 教学解析；
- 给学生的提示。

### `alternative_methods`

记录除了主要方法之外，其他确实可行的解法。

例如：

```text
primary_method:
泰勒展开

alternative_methods:
洛必达法则
等价无穷小比较
```

只记录方法名称和必要适用条件，不写第二套完整答案。

### `inter_question_dependency`

只有在具体题目 A 的结果被具体题目 B 直接调用时，才标注题间依赖。

例如：

```text
同一大题第 (2) 问必须使用第 (1) 问的结果
```

以下都不算题间依赖：

- A 和 B 同一章；
- A 和 B 同一知识点；
- A 比 B 简单；
- 建议先做 A 再做 B；
- A 的能力是 B 的前置。

没有直接依赖就写：

```text
none
```

### `isomorphic_relation`

记录不同题目之间的同构解题结构。

至少说明：

```text
cluster_id
structural_invariant
transfer_axis
```

例如：

```text
cluster_id:
LIMIT_HIGHER_ORDER_01

structural_invariant:
识别主导阶并提取首个非零项

transfer_axis:
函数形式变化、参数变化、题型变化
```

同构不是重复：

```text
重复
= 题目可能是同一道题

同构
= 题目不同，但解题骨架相同
```

## 跨层控制字段

### `review_status`

正式状态只有：

```text
candidate
verified
needs_review
not_applicable
```

含义：

```text
candidate
= 初步提出，尚未充分审核

verified
= 已依据题干、考纲、教材或评分证据核对

needs_review
= OCR、图示、来源冲突或存在多个合理解释

not_applicable
= 该字段不适用于这道题
```

`DEMO_ONLY` 只能表示示范记录，不是正式审核状态。

审核状态最好按字段记录：

```text
official_scope_status
main_knowledge_status
score_mapping_status
```

### `confidence`

置信度也应按字段记录，不要只给整题一个总分。

```text
scope_confidence
main_knowledge_confidence
score_mapping_confidence
isomorphic_confidence
```

`confidence` 和 `source_reliability` 永远不能互换。

## 对草案最后两个问题的最终回答

### 问题一：L2 核心题全量是否是 431 + 846 + 876？

**按当前项目优先级，是。**

```text
数学一真题：431
张宇基础30讲：876
408真题：846
合计：2153
```

但要严格区分两个口径：

```text
L2 核心训练标注范围：
2153 题

目标考试统计范围：
数学一 + 408 = 1277 题
```

张宇基础 30 讲可以进入核心训练标签，但不能进入数学一目标考频、目标分值和考试覆盖率统计。

### 问题二：`candidate_main_ability` 是否改为 `candidate_main_knowledge`？

**是，应该改。**

最终统一为：

```text
L1 candidate_main_knowledge
        ↓ 审核
L2 main_knowledge
```

同时保留：

```text
L2 assessed_construct
```

用来描述学生需要表现出的能力行为。

不再使用：

```text
audited_main_ability
```

这样以后不会再出现：

```text
候选主能力
审核主能力
主知识点
被测能力
```

四个名称互相重叠的问题。

> 我有一个问题啊，居然现在每一个题我们。搞了这么多标签，这和一开始源文件是不是偏差有点大呀，那现在怎么办啊，会影响源文件的实施吗
>
> User context
>
> Attachments:
> - 完整执行协议.md: `D:/考研动态学习项目/完整执行协议.md`

你的感觉是对的：**表面上看，L0—L3 比原始题库字段多了很多，不能把这些东西直接塞回源文件。**

但这不意味着源文件被破坏，也不意味着原来的执行协议失效。真正的问题是：之前展示的 L3 JSON 把“原始题目、知识标签、方法信息、评分信息、运行状态”全部放在了一份展开文件里，看起来像每道题都增加了几十个标签。

## 正确关系

```text
原始题库
= 不可变的题目档案

L0—L3
= 挂在题目 ID 上的派生标注

Teacher / Evaluator
= 根据需要读取不同标注视图
```

应该是：

```text
raw_question
    ↓ question_id
question_l0
question_l1
question_l2
question_l3
question_usage_roles
attempts
```

而不是：

```text
把所有标签直接写进原始 Markdown 题库
```

原始题库只负责保存题目本身和原始事实。标签应当通过唯一 `question_id` 外挂。

## 其实并不是每道题都有这么多“标签”

需要区分“知识点标签”和“辅助字段”。

真正参与考频统计的主要是：

```text
main_knowledge
secondary_knowledge
```

其他内容不是同一种标签：

```text
official_scope_coarse
= 考纲位置

label_provenance
= 标签判断依据

primary_method
= 解题方法

prerequisites
= 前置能力

difficulty_band
= 题目难度

score_units
= 评分结构

evidence_steps
= 得分证据

isomorphic_relation
= 题目结构关系
```

不能把这些全部当成“知识点标签”去统计。

尤其是：

- 方法不计入主知识点考频；
- 前置能力不计入主知识点考频；
- 评分操作不自动变成知识点；
- 次知识点不独立解释成一份完整分值；
- 同构关系不是重复标签。

## 也不是所有题都要完成 L3

这是最关键的范围控制。

```text
L0：全库完成
L1：全库完成
L2：核心题全量，其他题分层
L3：实际需要时完成
```

按当前项目优先级：

```text
L2 核心训练范围：
数学一真题 431
张宇基础30讲 876
408真题 846
合计 2153
```

但是：

```text
目标考试统计范围：
数学一真题 431 + 408真题 846
= 1277
```

张宇 30 讲虽然是核心训练来源，但不能并入数学一的目标考频和目标期望分值。

数学二、数学三、1000 题、王道、408 经典题等，不需要全库一次性做 L3。只有真正被调用、进入诊断、审计或训练时，才补 L3。

所以 8125 道题不是都要立即生成完整的 L3 结构。

## 原始执行协议没有失效

实际上，协议原本就把这些东西分开了：

```text
papers
= 试卷和来源信息

question_atoms
= 题目原子和原始事实

question_tags
= 知识点、方法、前置、难度、同构等标签

ability_graph
= 能力之间的前置和共学关系

attempts
= 学生实际作答记录
```

这才是正确架构。

之前的 50 题 L3 文件只是一个“展开后的标注结果”，方便检查；它不应该成为原始题库的新格式。

## 现在应该怎么处理

建议固定成四类文件：

```text
questions_raw

question_annotations
```

所以后面还需要做这些事。

**一、先填写执行合同**

你说的目标分数和时间，属于协议里的 `execution_contract_v1`，至少要确定：

- 数学一目标分、保底分；
- 408目标分、保底分；
- 考试日期；
- 每周真正可用的净学习时间；
- 数学一和408的每周时间分配；
- 两科各自的最低保证时间；
- 数学一唯一主课程和主资料；
- 408唯一主课程和主资料；
- 真题、官方答案、权威解析的来源；
- 默认学习块长度，协议默认45分钟；
- 系统整理、人工复核、数据维护合计不超过每周学习时间的10%。

这里不是简单“收集很多资料”。必须确定每科的主干资料，其他资料只能作为辅助来源，不能让资料无限扩张。

**二、把题库变成可以运行的数据**

即使标签已经打完，还要做一次结构性 QA：

- 每个题目和小问是否有唯一 `item_id`；
- 选择题、填空题、解答题是否正确拆成统计单元；
- 原始年份、题号、题型、分值是否与原题一致；
- 每个原子题是否恰好一个主知识点；
- secondary 标签是否超过上限；
- 评分单元之和是否超过原题分值；
- 数学一、数学二、数学三、408是否混库；
- 原题来源和标签来源是否分开；
- 原始题目是否保持不可修改；
- 标签置信度、审核状态、待复核项是否完整。

这一步主要可以用脚本完成，不需要重新人工理解每道题。人工只处理脚本发现的异常。

**三、建立能力结构，而不只是知识点标签**

协议要求另外建立 `ability_graph`。它不是给题目再加一堆标签，而是把知识点整理成可学习的能力包：

- 一个能力包具体要会做什么；
- 哪些是硬前置；
- 哪些只是软前置；
- 哪些能力应该一起练；
- 它对应考纲中的什么位置；
- 达到什么标准才算进入下一阶段。

例如“高阶极限”不能只作为一个标签，还要明确它可能包含：

- 判断需要展开到几阶；
- 识别前几项会不会抵消；
- 使用合适的展开或等价变形；
- 提取首个非零项；
- 在陌生题型中迁移。

题库标签告诉系统“题目涉及什么”，能力图告诉系统“你应该按什么顺序学”。

**四、计算目标考试的题目统计**

这一步是建立考试模型 E，数据范围必须严格限制：

- 数学一统计只使用数学一真题；
- 408统计只使用408真题；
- 数学二、数学三、经典题、王道题、1000题不能进入目标分数统计。

需要计算：

- 各知识点的近年出现频率；
- 对应分值；
- 题型分布；
- 常见组合；
- 近年权重；
- 样本数量和不确定性；
- 哪些知识点是高分值但当前薄弱；
- 哪些能力是其他能力的硬前置。

数学二、数学三和辅助练习题仍然有用，但只能作为迁移训练、补充练习和陌生题训练，不能证明数学一或408的目标得分概率。

**五、确定题目的使用角色**

同一道题不能只存在一个“用途”。需要生成或确认这些视图：

- `RAW`：原始题库，永久不改；
- `TARGET_PRIOR`：教师用于看目标考试先验统计；
- `STARTUP`：启动阶段使用的题；
- `TRAIN`：日常教学和练习；
- `ADAPTIVE_DIAGNOSTIC`：自适应诊断；
- `FIXED_AUDIT`：固定审计题；
- `SEALED`：封闭模拟考试；
- `AUX_OFFPOLICY`：辅助资料题。

尤其要提前确定：

- 数学一最早的三套可比真题；
- 408最早的三套可比真题；
- 固定审计题；
- 封闭模拟题；
- 哪些题教师永远不能提前看到。

固定审计题和封闭题必须与日常训练隔离，否则测出来的是记忆，不是独立能力。

**六、建立你的学生模型 S**

这是标签完成后最重要、也是标签无法替代的部分。

每次你做题，都要记录：

- 是否独立识别出考点；
- 是否能独立完成步骤；
- 是否能迁移到陌生变式；
- 是否在规定时间内完成；
- 过48到72小时后是否还能完成；
- 首次得分；
- 用时；
- 获得了几级提示；
- 错误类型；
- 下一次复习时间。

协议中的能力状态大致是：

`untouched → encountered → working_mastery → certified → stable`

其中“看懂讲解”不等于掌握。达到 `working_mastery` 至少要有两道未见过的近变式题，在 L0 独立状态下达到约80%；达到 `certified` 还要经过延迟混合冷测。

**七、正式运行五日启动阶段**

即使所有标签都做完，也不能直接把8125道题全部投入训练。协议要求先做启动阶段：

- 数学一选三套较早的完整真题；
- 408选三套较早的完整真题；
- 只做整体摸底和代表性题目；
- 每科选约24到36个锚点题；
- 锚点题经历独立尝试、分级提示、解释机制、陌生近变式、48到72小时冷测；
- 识别你当前能做、半会、完全不会的能力；
- 找出真正缺失的硬前置；
- 建立第一版当前学习前沿 `current_frontier`。

启动阶段的作用不是给你算一个最终基线，而是建立第一张“从哪里开始学”的地图。启动最多25个有效学习小时或5个日历日，以先到者为准，第5天必须进入正常学习。

**八、建立教师、评估器和复习队列**

最后才是系统的日常闭环：

- Teacher根据目标分值、当前薄弱程度、前置解锁价值和预计耗时选择下一能力包；
- 每天先处理到期复习，再学当前前沿能力；
- 每周根据实际得分、复习债务、固定审计结果和时间收益调整数学一/408的下周时间；
- Independent Evaluator负责自适应诊断、固定审计和封闭模拟；
- 教师不能提前读取固定审计题和封闭题；
- 每周保留配置版本和调整原因；
- 到阶段节点做封闭整卷，根据独立结果调整路线。

因此，完成 L0-L3 后的最小必要顺序是：

1. 填写执行合同；
2. 完成题库结构 QA；
3. 建立能力图和前置关系；
4. 计算数学一、408目标统计；
5. 确定题目使用视图、启动题、审计题和封闭题；
6. 建立做题记录、能力状态和复习队列；
7. 完成五日启动；
8. 进入“教学 → 变式 → 延迟冷测 → 更新状态 → 每周调整”的正常循环。

可以脚本化的主要是题库校验、统计、队列生成、复习日期、报表和异常检测。必须由你亲自提供的，是目标与时间约束、真实独立做题、用时、提示情况、冷测结果和每周执行情况。

最关键的一句话是：

> **L0-L3完成，不等于备考系统完成；它只完成了“题库理解层”。接下来必须用你的真实做题数据建立学生模型，再让教师和评估器开始闭环运行。**

而且不必等所有辅助题都精标完才开始学习。按照原协议，真正影响启动的核心是执行合同、数学一/408真题、主课程、启动题和最小记录系统；其他资料和精细标签可以在学习过程中按需补充。
